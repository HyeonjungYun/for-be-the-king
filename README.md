# For be the King

**자체 C++ IOCP 게임 서버 + Unreal Engine 5.8 클라이언트.**
엔진 리플리케이션을 쓰지 않고 네트워크 계층을 바닥부터 직접 구현한 멀티플레이 프로젝트입니다.

탑다운 PvPvE 익스트랙션 게임 — 30명이 한 던전 층에 들어가 파밍하고, 제한시간 안에 탈출해야
장비를 들고 나옵니다. 죽으면 들고 있던 장비를 전부 떨어뜨립니다.

## 개발 과정에서 풀어 온 문제

측정 → 원인 규명 → 수정 → 재측정을 날짜순으로 기록하며 진행했습니다. **틀린 가설과 계측기 오류도 지우지 않고 남겼습니다.**

### 1. 30명에서 처리 지연 33 ms — 병목은 대역폭이 아니라 호출 수였다 (2026-08-14)

- **증상**: 30명 동시 접속에서 처리 지연 P95 가 기준(16.6 ms)의 두 배인 33 ms.
- **원인**: 3 · 8 · 16 · 30명으로 늘리며 잰 값을 정규화하니 부하가 인원의 제곱에 비례했다. 이동 패킷이 올 때마다 나머지 전원에게 즉시 되쏘는 구조라 `Send` 호출이 N² 으로 늘었다.
- **수정**: 이동을 33 ms(30 Hz) 동안 모았다가 한 번에 브로드캐스트 — 직렬화 1회 · 세션당 `Send` 1회.
- **결과**: P95 33 ms → **0.1 ms 이하**, 초당 `Send` **26,100 → 900회**. 그런데 대역폭은 16% 밖에 줄지 않았다 — 비용은 데이터 양이 아니라 **락과 `WSASend` 호출 수**였다. 부수 효과로, 클라가 초당 1,000번 보내도 서버 송신은 늘지 않는다.

### 2. 120명 — 1차 가설은 틀렸다 (2026-08-23)

- 30명 측정에서 "동시 입장이 O(N²)" 라고 지목해 입장을 배치화했다. **계측해 보니 주범이 아니었다** — 입장 30건 합계 5.7 ms, 처리 최대값은 60~72 ms.
- 진짜 원인은 같은 브로드캐스트였다. 120명이 서로를 전부 보면 틱마다 약 14,000회 `Send`. 방을 **4개 층으로 나눠 각자 독립 큐**를 갖게 해 O(N²) 를 층 안에 가뒀다.
- **결과**: 처리 최대값 −72% · 송신 48.5 → 12.7 Mbps. **인원이 4배인데 클라 한 명이 받는 양은 30명 때와 같다** (107 → 106 kbps).
- 측정 방법도 고쳤다. 최대값 하나로 "27% 개선" 이라 판단했다가, 같은 빌드를 4번 재니 16% 가 흔들려 철회했다. 이후 P95 · P99 를 1차 지표로 쓴다.

### 3. 멱등 지급 트랜잭션 — 그리고 제가 오독한 −38% (2026-09-03)

- **설계**: `request_id` 를 PRIMARY KEY 로 두고 **INSERT 를 먼저** 한다. 재요청은 중복 키(1062)로 튕기고, 그 실패가 곧 "이미 지급됨" 이다. "조회해서 없으면 INSERT" 는 두 요청이 동시에 오면 둘 다 지급한다.
- **결과**: 세션 8개가 같은 캐릭터에 8,000개 요청 → **정확히 1,000번 지급, 잔액 오차 0**.
- **데드락**: FK 검사가 걸던 공유 잠금 위로 배타 잠금을 올리다 수십 건 발생 → `SELECT … FOR UPDATE` 로 잠금 순서를 고정해 0건. 데드락이 나던 때에도 잔액은 정확했다 — 실패가 없어서가 아니라 실패해도 부분 반영이 남지 않아서다.
- **오독**: 처리량이 2,841 → 1,767 req/s(−38%)로 떨어진 것을 "`FOR UPDATE` 의 비용" 이라 기록했다. 대상을 8개로 흩어 다시 재니 **3,220 req/s** — 비용은 `FOR UPDATE` 가 아니라 "같은 행에 몰릴 때의 직렬화" 였다. 조건 하나를 상수로 둔 채 비교해서 생긴 오독이다.

### 4. 커버리지 77% — 숫자보다 먼저 찾은 use-after-free (2026-09-01)

- 커버리지 제외 목록이 정당한지 확인하려고 `DBConnectionPool::Connect` 를 읽다가, 연결 실패 경로에서 **해제한 포인터를 컨테이너에 넣고 성공을 반환**하는 코드를 찾았다 (use-after-free · 이중 해제 · 거짓 성공). DB 연결이 한 번도 실패한 적이 없어 드러나지 않았을 뿐이다.
- 회귀 테스트를 남겼다. 제외 목록을 넓히는 것은 숫자를 만드는 일이자 **읽지 않을 코드를 정하는 일**이다.

### 5. 리뷰 후속 — 운영 기본기부터 (2026-10-21)

- 서버 전체를 다시 읽고 "운영에 올리면 바로 드러날 것" 을 먼저 고쳤다. TCP_NODELAY 와 keepalive 는 헬퍼만 있고 **한 번도 켜진 적이 없었고**, 켜 보니 `setsockopt` 에 `bool` 1 바이트를 넘기던 헬퍼가 성공만 돌려주고 값을 적용하지 않고 있었다 (SO_REUSEADDR 도 같았다). getsockopt 로 확인하는 테스트를 남겼다.
- 정상 종료 경로가 없었다 (`while (true)`). 종료 신호를 받아 플레이어 저장 → 세션에 알림 → DB 큐 drain → 종료까지 **160 ms**. 런 끝 저장의 저널은 "첫 실패 뒤" 가 아니라 **큐에 넣기 전**에 쓴다 — 강제 종료 직후의 저장이 사라지던 구멍.
- 타이머가 15.6 ms 분해능 위에 있었다. steady_clock 으로 바꾸고 워커 대기를 다음 예약까지로 줄이자 예약 지연 **p95 ≤ 16.6 ms · 최대 11 ms → p95 ≤ 1 ms · 최대 2 ms**.
- 하트비트(5 s)와 유휴 끊기(30 s), 중복 로그인은 옛 연결을 끊는 kick-old, 로그인 전 패킷은 한 곳에서 차단, 고장 주입 훅은 배포 빌드에서 컴파일 제외, DB 는 root 대신 전용 계정, 클라 문자열이 닿는 SQL 은 prepared statement, 크래시 미니덤프, 매니저 락 순서 검사. 14,000줄 `Room` 은 이동 검증과 피해 계산부터 순수 함수로 떼어 테스트를 붙이기 시작했다 (347 → 363).

## 개발 방식

- **2026-06 ~ 10-03** — 게임 서버 코어 · 넷코드 · DB 연동 · 지급 트랜잭션 · 계측 · 테스트와 CI 를 직접 작성했습니다. IOCP · 세션 · JobQueue 뼈대는 온라인 게임 서버 강의에서 배운 구조를 따랐고, 그 위의 계측 · 부하 봇 · 이동 검증 · 비동기 DB · 멱등 지급 · 테스트는 직접 설계했습니다. 이 기간 AI 코딩 에이전트(Claude Code)는 설계 문서 · 코드 리뷰 · 수정 제안에 쓰고, 적용은 읽고 판단한 뒤 손으로 했습니다.

## 받아서 실행해 보기 (한 PC 묶음)

빌드 없이 플레이해 볼 수 있는 묶음을 [Releases](../../releases) 에 올려 두었습니다 (zip 약 550 MB, 풀면 1.2 GB).
게임 서버 · 인증 서버 · MySQL · 클라이언트가 한 폴더에 들어 있고, **설치 없이 이 PC 안에서만** 돌아갑니다.

```
1  zip 을 풀고 Start.bat      DB(3307) → 인증 서버(8080) → 게임 서버(7777) → 클라이언트
2  로그인 화면에서 [가입]      아이디 · 비밀번호 → 캐릭터 이름
3  베이스캠프                  길드장(위쪽 붉은 문 옆)에게 F → 1 → [입장] → 진입 지점 (R = 무작위)
4  AddBots.bat                 봇 30명이 같은 층에 들어온다 (PvP 상대 · 무작위 스킬 셋 + AI 두뇌)
5  Stop.bat                    전부 종료
```

- 필요: Windows 10/11 64비트 · DirectX 12 그래픽 카드. VC++ 런타임 오류가 나면 `client\Engine\Extras\Redist\en-us\vc_redist.x64.exe`
- 조작: WASD 이동 · 우클릭 유지 평타 · Shift / Q / E / R / Z / X 스킬 · F 대화 · 줍기 · Tab 소지품
- 묶음은 `Tools/package/package-bundle.ps1`(로컬 전용 도구)로 만들었습니다 — 클라 패키지 + `GameServer.exe` · `DummyClient.exe` + 인증 서버(.NET 런타임 포함 배포) + MySQL 8.0(필요한 파일만 · 스키마와 시드를 미리 넣은 DB)
- MySQL 8.0 Community Server 는 GPL v2 입니다 (`mysql\LICENSE`)

## 패키징 빌드 (클라이언트)

> ⚠️ **현재 외부 컴퓨터에서의 접속은 불가능합니다.** 패키지 클라는 서버와 같은 PC 에서만 실행 · 검증했습니다.
>
> | 접속 위치 | 상태 |
> |---|---|
> | 같은 PC (`127.0.0.1`) | ✅ 동작 확인 |
> | 같은 공유기의 다른 PC (LAN) | ⚠️ 서버를 `0.0.0.0` 에 열고 방화벽을 여는 설정까지만 있다. 실제 다른 PC 로는 검증하지 않았다 |
> | 다른 네트워크 · 인터넷 | ❌ 불가능 — 공인 IP · 포트포워딩 · HTTPS(지금 인증이 http 라 비밀번호가 평문) · 게임 TCP 암호화가 모두 없다 |

Win64 · **Development** 로 만듭니다. 보스 예고 · 투사체 · 장판 표시가 아직 디버그 그리기라 Shipping 에서는 화면에서 사라집니다.

```
전제     에디터를 닫는다 (열려 있으면 빌드 · 쿡이 파일 잠금에 걸린다)
         애니메이션 팩 7 개(Archer · BCD_Anims · Dagger · Fighter_Animations · Spear · EssentialAnimation ·
         GhostSamurai_Bundle)는 마켓플레이스 에셋이라 저장소에 없다 — S1\Content\ 에 따로 설치해야 동작이 나온다

1  빌드 · 쿡 · pak
   C:\Unreal5.8\UE_5.8\Engine\Build\BatchFiles\RunUAT.bat BuildCookRun -project="<저장소>\S1\S1.uproject" ^
       -noP4 -utf8output -platform=Win64 -clientconfig=Development ^
       -build -cook -stage -pak -archive -archivedirectory="<출력 폴더>" -prereqs

2  서버 데이터 동봉 — 클라가 실행 중에 S1 폴더 옆 Server\Data 의 CSV 를 읽는다
   robocopy Server\Data "<출력 폴더>\Windows\Server\Data" *.csv

3  실행 — 서버 주소는 명령줄로 덮어쓴다 (기본값 127.0.0.1)
   "<출력 폴더>\Windows\S1.exe" -windowed -ResX=1280 -ResY=720 ^
       "-ini:Game:[/Script/S1.S1LoginSubsystem]:AuthServerUrl=\"http://<호스트 IP>:8080\"" ^
       "-ini:Game:[/Script/S1.S1LoginSubsystem]:GameServerHost=<호스트 IP>"
```

- 결과는 약 1.1 GB 입니다. 테스터 PC 에는 `Windows` 폴더만 복사하면 되고 UE 는 필요 없습니다. VC++ 런타임이 없다는 오류가 나면 `Engine\Extras\Redist\en-us\vc_redist.x64.exe` 를 설치합니다.
- 호스트는 위 **빌드 · 실행**의 1~3(DB · 게임 서버 · 인증 서버)을 띄웁니다. 서버는 기본으로 `127.0.0.1` 에만 열려 있어 다른 PC 의 접속을 받지 않습니다. LAN 시험용 설정은 `FBTK_BIND_ADDRESS=0.0.0.0`(게임 서버) · `Kestrel__Endpoints__Http__Url=http://0.0.0.0:8080`(인증 서버) · 방화벽 TCP 7777 · 8080 이지만, 위 표처럼 검증되지 않았습니다.
- 쿡 대상은 `S1/Config/DefaultGame.ini` 에 정해 두었습니다. 맵은 `Floor1` 하나만 쿡하고, CSV 경로로만 불리는 애니메이션 151 개 폴더는 항상 쿡합니다(쿠커가 스스로 찾지 못한다). 개발용 로그인 토큰은 `IniKeyDenylist` 로 패키지에서 뺍니다.
- 🔴 인증이 http 라 비밀번호가 평문으로 오갑니다. 인터넷에 열면 안 됩니다.
