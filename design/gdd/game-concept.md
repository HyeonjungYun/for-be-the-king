## Elevator Pitch

> 넓은 던전에 30명이 동시에 들어가 상자를 뒤지고, 30분 안에 탈출 타워에서 60초를 버텨야 살아 나오는 **탑다운 익스트랙션 게임**. 캐릭터 레벨은 없다 — 힘은 오직 손에 든 장비에서 나오고, 죽으면 그 장비를 전부 가방으로 흘린다.
>
> 그리고 **싸우지 않는 길이 있다.** 개활지 파밍은 수익이 낮지만 사람을 거의 만나지 않는다.

## Core Fantasy

**"내가 들고 있는 이것이 곧 나다."**

이 게임에는 캐릭터 성장이 없다. 100시간을 해도 캐릭터는 처음과 같다. 달라지는 것은 **손에 들린 것**뿐이다.

그래서 모든 장비가 무겁다. 좋은 무기를 얻은 순간부터 그것은 자산이자 부채가 된다. 지금 나가면 지킬 수 있고, 한 발 더 들어가면 더 얻거나 전부 잃는다. 30분 뒤에는 무조건 결판이 난다.

> **"무겁다"는 은유다.** 무게·소지한도(encumbrance) 시스템은 없다. 심리적 부담을 뜻한다.

그리고 던전에는 29명이 더 있다. 그들도 같은 계산을 하고 있다.

## Unique Hook

> **Dark and Darker의 전손 긴장, AND ALSO 탑다운 시점 · 기존의 2~3배 인원.**

기존 익스트랙션 게임은 전부 1인칭/3인칭이고, 소규모 인스턴스(6~18인)로 돌아간다. 탑다운 시점은 **시야가 곧 정보**가 되는 장르인데, 여기에 익스트랙션의 판돈을 얹은 사례가 없다.

부차적 훅 세 가지:

- 🆕 **싸우지 않는 길이 있다** — 개활지 파밍은 수익이 낮은 대신 조우가 드물다.
  **익스트랙션 장르에서 처음이다.** Tarkov도 Dark and Darker도 들어가면 무조건 판돈이 걸린다.
- **캐릭터 레벨 없음** — 장비 레벨만 존재하며, **강탈당하는 순간** 1로 초기화된다. 등급만 남는다. 강자가 강함을 물려줄 수 없다.
- **인원이 곧 힘** — 대부분의 게임이 억제하는 다구대일의 우위를 오히려 보장한다. 이를 뒤집는 유일한 길은 파티 결성권 자체를 포기하는 것이다.

> **인원을 100 → 30으로 낮춘 이유** (2026-08-11).
> 탑다운은 인원이 많을수록 화면 판독이 어려워진다. 20명 이상이 한 곳에서 싸우면
> "전투"가 아니라 난장판이 된다. **P4("정보가 가장 비싼 자원")를 지키려면 인원이 적어야 한다.**
> 숫자를 팔기는 어려워졌지만 게임 재미가 우선이다.

### Key Dynamics (Emergent player behaviors)

설계하지 않았으나 규칙에서 자연히 발생할 행동들:

- **빈 집 추적** — 상자가 비었다는 것은 누군가 이 층에 있고 지금 좋은 것을 들고 있다는 뜻이다. 파밍 실패가 사냥의 시작이 된다
- **탈출 치킨게임** — 게이지를 채우면 구역 내 전원이 나간다. 먼저 채우는 자가 어그로를 끌고, 숨은 자는 무임승차한다. 체류 타이머가 오래된 사람이 결국 나선다
- **자경단** — 고티어는 저층에서 파티를 못 맺는다. 저티어들이 뭉쳐 고티어 솔로를 사냥하는 구도가 자생한다
- **집 앞 대기** — 몬스터와 싸우느라 지친 파티를 노리고 기다리는 기회주의
- **귀환로 매복** — 탈출 타워가 개활지에 있어, 가장 많이 들고 있는 순간이 가장 노출된 순간이 된다
- **탈출존 캠핑** — 게이지 알림이 공짜 정보다. 던전에 들어가지 않고 타워 근처만 순회하는 전략이 성립한다. ⚠️ 인구가 늘면 지배 전략이 될 수 있다 — Design Risks에서 추적
- **개활지 은둔** — 집을 아예 노리지 않고 개활지만 도는 플레이. 수익은 낮지만 조우가 드물어 **꾸준히 살아 돌아온다.** 의도된 선택지다

### Core Mechanics (Systems we build)

| Mechanic | Serves Which Dynamic |
| ---- | ---- |
| 상자 파밍 (확률 차등: 집 高 / 개활지 低) | 빈 집 추적, 탐색 |
| **넓은 개활지 + 소수의 집** — 조우 밀도가 공간에 따라 갈림 | **위험/수익 이중 루트** (개활지 은둔 vs 집 공략) |
| 30분 개인 체류 타이머 → 초과 시 사망 + 가방 드랍 | 탈출 치킨게임, 압박 |
| 60초 탈출 게이지 (인원 무관 · 이탈 시 역행 · 완충 시 구역 전원) | 강제 협력 딜레마 |
| 사망 시 전 소지품 가방 드랍 (10분 루팅 가능) | 귀환로 매복, PvP 동기 |
| 아이템 레벨 초기화 (강탈 시) + 등급 유지 | 스노우볼 억제, PvP 보상 유지 |
| 아이템레벨 총합 기반 티어 게이팅 | 인구 순환 |
| 티어차 기반 파티 인원 제한 | 자경단 |
| 하드 CC = 무기 부위 전용 (캐릭터당 1개) | 다구대일 성립 + 체인 CC 상한 |
| 미니맵 없음 → 근거리 레이더만 | 길찾기 = 실력, 정보 은닉 |
| "고독한 길" 장비 계열 (파티 영구 불가) | 솔로 1급 경로 |

## Player Motivation Profile

### Primary Psychological Needs Served

| Need | How This Game Serves It |
| ---- | ---- |
| **Autonomy** (자율성) | 어느 층·어느 집·언제 탈출할지 전부 선택. 협동/배신/솔로 모두 열려 있음. 시스템이 강제하는 플레이스타일 없음 |
| **Competence** (유능감) | 열세를 실력으로 뒤집는 것이 유일한 상향 경로. **동수 교전에서는** 장비가 아니라 판단이 승패를 가름 (다구대일에서는 P1이 우선한다 — § 전투의 승률 목표 참조) |
| **Relatedness** (관계성) | 파티 · 배신 · 탈출 타워의 즉석 협력. 단, 관계는 항상 불안정하도록 설계 |

### Player Type Appeal (Bartle Taxonomy)

| Type | Appeal | Why |
| ---- | ---- | ---- |
| **Killer** | ★★★★★ | 판돈 있는 PvP. 이기면 상대 것까지 |
| **Explorer** | ★★★★☆ | 상자 탐색 · 정보 추리 · 빌드 실험 |
| **Socializer** | ★★☆☆☆ | 배신이 상시 가능하고 시스템이 보호하지 않음 |
| **Achiever** | ★★☆☆☆ | 캐릭터 레벨은 없으나 **창고 축적이 실제 경로다.** 개활지 은둔 루트로 꾸준히 쌓을 수 있다 |

> Achiever를 크게 포기한 것은 P2(힘은 손에 든 것에서만)의 의도된 대가다.
> 다만 **2026-08-11 개활지 루트 확정으로 ★1 → ★2로 올랐다** — 저위험 파밍으로 창고를 불리는
> 느긋한 경로가 생겼기 때문이다. 여전히 레벨·특성 트리 같은 진행 지표를 원하는 유저는 좌절한다.

### Flow State Design

| 구간 | 난이도 곡선 | 플레이어 스킬 |
| ---- | ---- | ---- |
| 개활지 이동 | 낮음 (저등급 상자, 약한 몬스터) | 경계 · 정보 수집 |
| 집 진입 판단 | 중간 (지금? 기다릴까? 다른 집?) | 리스크 평가 |
| 집 내부 교전 | 높음 (강력한 몬스터 + 난입 가능) | 전투 · 자원 관리 |
| 귀환로 | 최고 (가장 많이 들고 있음 + 개활지 노출) | 회피 · 경로 선택 |
| 탈출 게이지 60초 | 최고 (고정 위치 + 알림 발생) | 방어 · 판단 |

**긴장 곡선이 세션 후반으로 갈수록 상승**한다. 지루한 구간은 개활지 이동뿐이며, 이는 의도적 휴지다.

## Core Loop

### Moment-to-Moment (30 seconds)

> ⚠️ **미결** — 교전의 손맛(빠르고 정확 / 무겁고 신중 / 화려하고 폭발적)이 아직 확정되지 않았다. 전투 프로토타입을 만들며 결정한다.

확정된 것: 탑다운 시점, WASD 이동 + 커서 조준(분리), 우클릭 평타, 6키 스킬(`Shift`/`Q`/`E`/`R`/`Z`/`X`), 스킬은 장비에 귀속.

### Short-Term (5-15 minutes)

```
개활지 진입 (베이스캠프에서 층 직행)
   ↓  저등급 상자 · 약한 몬스터 · 낮은 확률로 고등급
집 판단 — 지금 들어갈까 / 기다릴까 / 다른 집으로
   ↓
집 진입 → 강력한 몬스터 교전 → 고등급 상자 파밍
   ↓  (다른 파티 난입 가능 · 빈 집이면 추적으로 전환)
개활지 횡단 → 탈출 타워          ← 가장 위험한 구간
   ↓
60초 게이지 → 탈출
```

**한 사이클 = 집 하나를 노리고 갔다 오는 것.**

### Session-Level (30-120 minutes)

세션 = **30분 체류 한 판**. 리스폰이 30분이므로 사실상 "층 한 바퀴".

시간 예산 (§ 공간의 확정 수치 기준):

```
30분 = 1800초
  − 탈출 게이지                 60초
  − 타워까지 귀환 (평균)       ~60초
  = 실제 파밍 가능             ~1680초

집 사이 이동 (집 5개 균등 배치, 인접 간격 ~125m ÷ 3.4m/s)  ≈  37초
집 하나 클리어 (몬스터 + 파밍)                             ≈  120~180초
→ 사이클 ≈ 157~217초
```

**집 5개를 전부 도는 데 약 13~18분.** 30분 세션에 **시간이 남는다.**
리스폰이 30분이라 같은 집을 두 번 털 수 없으므로, 남는 시간은 다음 중 하나로 채워진다.

- **개활지 파밍** — 저수익·저위험 루트가 여기서 의미를 갖는다
- **PvP 조우·회피** — 다른 플레이어와의 상호작용
- **빈 집 추적** — 먼저 털린 집의 흔적을 보고 사냥으로 전환

> **이것이 개활지 루트가 성립하는 구조적 이유다.** 집만으로는 세션이 채워지지 않는다.

> ⚠️ MVP는 **집 3개** → 약 10분. 세션의 절반. 초기 검증에는 충분하다.
> ⚠️ PvP 조우·회피 시간은 계산에 없다. 실측은 플레이테스트에서.

자연스러운 중단 지점: 탈출 성공 직후. 베이스캠프에서 정비하고 다음 판을 결정한다.

### Long-Term Progression

**캐릭터는 성장하지 않는다.** 성장하는 것은 세 가지다.

1. **창고 자산** — 반출한 장비가 쌓인다. **상한 있음** (§ 성장 · 손실 참조)
2. **아이템 레벨** — 재화를 써서 개별 장비를 강화 (Tier 3)
3. **플레이어 자신의 실력** — 층 지리, 리스폰 타이밍, 매복 지점, 상대 심리

아이템레벨 총합이 티어를 결정하고, 티어가 접근 가능한 층을 결정한다. **죽으면 총합이 떨어져 하위 티어로 내려간다.**

> ⚠️ **"자동 순환"이라고 쓰지 말 것.** 창고에 예비 세트가 있으면 강등이 즉시 상쇄된다.
> 순환은 **창고 재고가 소진된 뒤에** 일어난다. 그래서 창고 상한이 이 메커니즘의 실질적 브레이크다.
> 신규 유저(재고 0)에게는 즉시 작동하고, 베테랑에게는 지연되어 작동한다 — 이는 **의도된 비대칭**이며,
> 다시 죽을 리스크가 상존하는 한 허용 가능하다고 판단했다 (2026-08-11 결정).

### Retention Hooks

- **다음 판 심리** — 30분이 짧아서 "한 판만 더"가 성립
- **잃은 것 되찾기** — 방금 뺏긴 장비를 그놈이 아직 들고 있을 수 있다
- **미완의 집** — 못 털고 나온 집이 있다
- **빌드 실험** — 새로 얻은 장비 조합을 시험해보고 싶다

## Game Pillars

### Pillar 1: 숫자가 곧 힘이다

인원이 많은 쪽이 항상 유리하다. 뒤집는 유일한 길은 명시적 대가를 치르는 것이다.

**설계 테스트**: **인원수에 반비례해 강해지는** 장치(광역 쓸어담기, 1인 캐리 빌드, N명 이상에게 걸리면 약해지는 CC)를 넣을지 고민된다면 → **넣지 않는다**

> **CC 저항력은 이 테스트를 통과한다.** 장비에 붙은 대칭적 스탯이며, 4명도 각자 올릴 수 있다.
> 금지되는 것은 "소수라서 받는 보정"이지 "누구나 장비로 사는 방어력"이 아니다.

> ⚠️ **P1의 실행 장치가 하나 바뀌었다.** 2026-08-10 시점에는 "CC 점감 완전 제거"가 P1의 실행 장치였으나,
> 2026-08-11에 CC 저항력 스탯 도입과 함께 폐지되었다. 현재 P1을 강제하는 것은
> **① 순수 화력 배수** ② **파티 인원 제한** ③ **하드 CC 총량이 인원에 비례** 셋이다.

### Pillar 2: 힘은 손에 든 것에서만 나온다

캐릭터에 축적되는 힘은 없다. 모든 능력은 장비에 붙어 있고, 장비는 잃을 수 있다.

**설계 테스트**: 새 성장 요소를 캐릭터에 붙일지 장비에 붙일지 고민된다면 → **장비에 붙인다**

### Pillar 3: 시스템은 처벌하지 않는다

배신·닌자루팅·학살을 규칙이 벌하지 않는다. 억제는 다른 플레이어가 한다.

**설계 테스트**: 나쁜 행동을 막고 싶다면 → **페널티를 주지 말고, 플레이어가 응징할 수 있는 구조를 만든다**

### Pillar 4: 정보가 가장 비싼 자원이다

위치·의도·상태는 기본적으로 감춰져 있다. 드러내는 순간 대가가 따른다.

**설계 테스트**: 편의를 위해 정보를 표시할지 고민된다면 → **감춘다**

### Pillar 5: 얻는 순간 잃을 것이 생긴다

가치를 획득할수록 위험이 커진다. 안전한 축적은 없다.

**설계 테스트**: 획득 후 안전을 보장하는 장치를 넣을지 고민된다면 → **넣지 않는다. 대신 탈출을 선택지로 만든다**

### 필러 간 긴장

- **P1 ↔ P4** — 숫자는 힘이지만 정보가 그것을 뒤집을 수 있다. "고독한 길"이 성립하는 자리
- **P3 ↔ P1** — 파티 인원 제한은 처벌이 아니라 **구조적 제약**이다. 고티어가 저층에 가는 것은 자유이며, 다만 혼자 가야 한다
- **P1 ↔ P5 — 가장 위험한 충돌.** 조직된 파티에게는 P1이 P5를 상당 부분 흡수한다.
  4인 파티는 파밍 처리량이 4배이고, 탈출 게이지도 1명만 세워두면 충전되므로 60초 취약 구간이
  솔로에 비해 훨씬 얕다. **결과적으로 P5("안전한 축적은 없다")가 온전히 작동하는 대상은 솔로·듀오다.**

  이것을 **의도된 비대칭으로 수용한다.** 파티를 맺을지는 자유이고, 그 대가는 전리품 분배와
  배신 리스크다. 다만 **문서가 "모두에게 긴장이 상승한다"고 쓰지 않도록 주의할 것** —
  Flow State Design의 곡선은 솔로 기준이다.

### Anti-Pillars (What This Game Is NOT)

| 하지 않을 것 | 위반하는 필러 |
| ---- | ---- |
| **캐릭터 성장을 만들지 않는다** — 레벨·스탯·특성 트리 없음 | P2 |
| **배신을 처벌하지 않는다** — 평판·바운티·강제 페널티 없음 | P3 |
| **미니맵을 만들지 않는다** — 전체 지형도·적 위치·전체 킬로그 없음. 근거리 레이더만 | P4 |
| **안전한 축적 수단을 만들지 않는다** — 전액 보전 보험, 던전 내 PvP 금지 구역 | P5 |
| **신규 유저를 보호하지 않는다** — 튜토리얼 보호막·신규 전용 서버·초보 매칭 없음 | P1 |

> **신규 유저 보호를 넣지 않는 것은 명시적 결정이다** (2026-08-11).
> 신규 유저는 첫 세션부터 숙련자와 같은 층에서 만나고, 아무 설명 없이 죽을 수 있다.
> 이것이 익스트랙션 장르 최대 이탈 지점임을 인지하고 감수한다.
> **"30분 세션이라 부담이 낮다"는 이 문제의 완화책이 아니다** — 세션 길이와 무관한 문제다.
> 실제 완화 수단은 **온보딩 없이도 읽히는 비주얼 언어**뿐이다 (`art-bible.md` §"읽히지 않으면 존재하지 않는다").

## 핵심 시스템 규칙 (확정)

### 성장 · 손실

| | |
| ---- | ---- |
| 캐릭터 레벨 | **없음** |
| 아이템 레벨 | 게임 내 재화로 강화. 장비에 붙은 스킬의 위력을 결정 |
| 아이템 등급 | 고정. 드랍·강탈 시에도 유지 |
| **레벨 초기화 트리거** | **강제 소유권 이전 시에만** — 사망 드랍 · 강탈 · 타인이 루팅 |
| **초기화되지 않는 경우** | **창고 반출 · 창고 인출.** 반출 성공한 장비의 레벨은 보존된다 |
| **PvP·몬스터 사망 시** | 소지·장착품 전부 가방으로 드랍 → **10분간 타 플레이어 루팅 가능** → 이후 소멸 |
| **타이머 만료 사망 시** | **전량 소멸. 가방 드랍 없음** — § 탈출 · 압박 참조 |
| 구출 | 길드가 베이스캠프로 구출 (퍼머데스 아님). **구출 수수료 없음** |

#### 창고

| | |
| ---- | ---- |
| **용량** | **장비 부위 수 × 5 슬롯** (부위 5개면 25칸) |
| 슬롯 규칙 | **부위 무관.** 무기만 25개를 넣어도 된다 |
| 골드 | 슬롯을 차지하지 않음 (별도 계정 재화) |

> 창고 상한이 **인구 순환의 실질적 브레이크**다. 상한이 없으면 예비 만렙 세트를 무한 축적해
> 티어 강등이 영구히 상쇄된다. 부위 수 × 5 = **예비 세트 약 5벌**이 의도된 천장이다.

#### 골드

| | |
| ---- | ---- |
| 형태 | **인벤토리 아이템.** 던전에 들고 들어가고 들고 나온다 |
| 소스 | 길드 전리품 매입 ⚠️ **매입 규칙 미정** — Open Questions |
| **PvP·몬스터 사망 시** | **30% 유지 / 70% 가방 드랍** (루팅 가능) |
| **타이머 만료 사망 시** | **30% 유지 / 70% 소멸** |
| **싱크** | **사망 시 창고 골드의 일정 % 차감** ⚠️ **% 수치 미정** |

> **골드는 P5의 유일한 예외다.** "사망 시 전부 드랍" 원칙에서 30%가 보호된다.
> 이 예외가 없으면 빈털터리가 되어 회복 경로가 막힌다.

> **싱크는 % 여야 한다.** 고정액이면 역진세가 된다 — 부자에게는 무의미하고 가난한 자에게는 치명적이다.
> 단, **창고 골드가 0인 신규 유저에게는 이 싱크가 작동하지 않는다.** 의도된 결과이며,
> 신규 유저에게 P5를 강제하는 것은 인벤토리 70% 드랍 쪽이 담당한다.

### 세계관 — 함몰된 고대 왕국

대륙 정중앙에 있던 **고대 왕국이 통째로 가라앉았다.** 그 자리에 던전이 생겼다.

#### 함몰의 원인 — 계승된 힘의 폭주

고대 왕국은 **엄청난 에너지를 다루는 기술**을 가졌고, 그 에너지를 **몸에 내재하는 왕의 핏줄**이 있었다.

```
왕의 핏줄은 죽기 전에 자신이 축적한 모든 에너지를 차기 왕에게 넘긴다.
   ↓  대를 거듭할수록 총량이 불어난다
마지막 왕에게 넘겨진 힘이 임계를 넘어 폭주했다.
   ↓
왕국 일대가 통째로 땅으로 함몰 · 축적된 에너지 전량이 방출
   ↓
그 에너지가 남아 던전이 되었다.
```

#### 이 설정이 결정하는 것들

| 질문 | 답 |
| ---- | ---- |
| **몬스터는 어디서 왔나** | 방출된 에너지가 변형시킨 것들 |
| **왜 4층이 가장 위험한가** | 궁궐 = 폭주의 진원. **에너지 농도가 가장 높다** |
| **왜 아이템에 레벨이 붙나** | 에너지가 물건에 스며든 것. 강화 재화 = 응축된 에너지 |
| **왜 강탈하면 레벨이 초기화되나** | 소유자가 바뀌면 **에너지 결속이 끊어진다** |
| **길드는 왜 이 짓을 하나** | 에너지와 유물의 회수 |
| **"왕이 된다"는 게 뭔가** | 에너지의 진원, 곧 왕좌에 닿는 것 |

> **제목의 아이러니.** 마지막 왕의 힘이 왕국을 멸망시켰다.
> 그렇다면 "왕이 되는 것"은 좋은 결말인가? — 서사 확장 시 활용할 것.

#### 구조

- **깔때기 구조** — 왕국 중심부일수록 깊이 떨어졌다. 따라서 **깊이 = 원래 왕국에서의 사회적 중심도**
- 건물들은 낙하 중 부서져 **대부분 한 층만** 남았다
- 길드가 이 던전을 관리하며, 탈출 타워를 설치하고 사망자를 구출하고 전리품을 매입한다

```
지상 ─────────────────────────  대륙
  1층   민가              평민
  2층   궁궐 외곽시설      하인 · 병사
  3층   낙하한 궁궐 파편   귀족
  4층   궁궐 본체         왕
```

> **제목 "For be the King"과 직결된다.** 4층 도달 = 왕좌 도달.
> 티어 게이팅이 난이도 구분이 아니라 **서사**가 된다.

> **"모든 건물이 단층"이 게임플레이 요구와 일치한다.** 탑다운에서 다층 건물은 2층이 1층을
> 가려 최악이다. 낙하 중 부서졌다는 설정이 이 제약을 자연스럽게 정당화한다.

상세 시각 규칙은 `design/art/art-bible.md` Section 6 참조.

### 공간

```
베이스캠프
  ├─▶ 1층  소모품 · 강화 재화        ← 모든 유저   · 평민 민가
  ├─▶ 2층  희귀 등급 중심             ← 2티어 이상  · 궁궐 외곽시설 (헛간 · 주방 · 병영)
  ├─▶ 3층  영웅 등급 중심             ← 3티어 이상  · 낙하한 궁궐 파편
  └─▶ 4층  전설 등급                  ← 4티어만    · 궁궐 본체 (알현실 · 왕실)
```

- 각 층은 **베이스캠프에서 직행**. 던전 내 층간 이동 없음 (허브 앤 스포크 구조 — "심리스"가 아니다)
- 층 구조 = **넓은 개활지 + 곳곳의 "집"(방 + 복도)**
- **집** = 그 층의 고등급 확률이 높은 곳. 그 층 기준 강력한 몬스터 배치
- **개활지** = 저등급 상자 + 약한 몬스터. 낮지만 0이 아닌 고등급 확률
- 몬스터·상자 리스폰 **30분** (체류 시간과 동일), **집별 독립 타이머**
- 탈출 타워는 **개활지에** 배치 — 귀환로가 가장 위험하도록

> ⚠️ **등급 명칭은 아트 바이블의 공식 4단계만 쓴다** — **일반 · 희귀 · 영웅 · 전설**
> (`art-bible.md` Section 4②). "희귀 장비"·"매우 희귀 장비" 같은 서술적 표현은 공식 등급명과
> 충돌해 드랍 테이블 작성 시 오해를 부른다. 위 표는 2026-08-11에 공식 명칭으로 정렬했다.

#### 확정 수치 (2026-08-11)

이동속도는 **라이즈 기본값**. 좌표 환산은 **1 LoL 유닛 = 1 UE 유닛(cm)** 으로 고정한다.

| 항목 | 값 | 산출 |
| ---- | ---- | ---- |
| 소환사의 협곡 | 약 15,000 × 15,000 유닛 | 기준점 |
| **층 크기** | **280 m × 280 m** | 78,400 m² — 협곡 **넓이 약 3.5배** |
| **층당 인원** | **30명** | 4개 층 = 총 120 동접 |
| **기본 이동속도** | **340 cm/s = 3.4 m/s** | 라이즈 340. UE `MaxWalkSpeed` 기본값 600 → **340으로 변경** |
| 층 횡단 | **82초** | 280 ÷ 3.4 |
| 층 대각선 | **116초** | 396 ÷ 3.4 |
| 집 간격 (5개 균등) | **125 m ≈ 37초** | 280 ÷ √5 |
| **카메라** | `TargetArmLength` **2,600** · FOV **60°** · pitch **−60°** | 화면 가로 30 m 역산 |
| **화면 가시 면적** | **약 585 m²** (30 m × 19.5 m) | 위 카메라값에서 도출 |
| **레이더 반경** | **22.5 m** | 화면 가로 절반 × 1.5 |

**밀도 검증** (카메라 확정 반영 — `movement-camera.md` Core Rule 8)

```
카메라 TargetArmLength 2,600 · FOV 60° · pitch −60°
→ 화면 30 m × 19.5 m  =  가시 면적 약 585 m²

30명 ÷ 78,400 m²        =  2,613 m² 당 1명
585 ÷ 2,613             =  동시 가시 ≈ 0.22명
```

> 🔴 **이전 문서의 "1.9명"은 근거 없는 수치였다.** "시야 반경 40 m"를 가정해 계산했는데,
> 그 40 m는 카메라에서 도출된 값이 아니라 **1.9라는 결과에서 역산한 것**이었다.
> 실제 LoL급 카메라(화면 가로 30 m)로 계산하면 **0.22명**이다.

**개활지는 의도적으로 희박하다.** 이것이 "싸우지 않는 길"을 만든다.
교전은 **집에서 일어나고**, 개활지는 이동·저수익 파밍·회피의 공간이다.

**집 개수**

```
집당 적정 교전 인원 5~8명   (탑다운 판독 한계)
30명 ÷ 6  =  집 약 5개
```

| 시점 | 집 개수 |
| ---- | ---- |
| **MVP** | **3개** |
| 최종 | 5개 (역산치) |

> **인원을 100 → 30으로 낮추면서 "집 3~5개"가 다시 맞는 수치가 되었다.**
> 100명 기준으로는 집당 20~33명이 몰려 데스매치가 됐지만, 30명 기준으로는 집당 6명이다.

> ✅ **카메라 확정 완료 (2026-08-11)** — `TargetArmLength` 2,600 · FOV 60° · pitch −60°.
> 상세와 역산 과정은 `design/gdd/movement-camera.md` § Core Rules 8.

> ⚠️ **개활지는 문서가 이전에 시사한 것보다 훨씬 비어 있다.** 82초를 걸어 횡단하는 동안
> 사람을 거의 만나지 못한다. 이는 **"싸우지 않는 길"이라는 설계 의도와 부합**하지만,
> **Key Dynamics의 "귀환로 매복"은 개활지에서 거의 발생하지 않는다** — 매복은
> 탈출 타워 주변처럼 사람이 모이는 지점에서만 성립한다.

| 티어 판정 | 착용 **아이템 레벨 총합** |
| 게이팅 | 자기 티어 **이하는 자유**, 초과는 차단 |
| 파티 인원 | 티어차에 따라 제한. **파티 내 최고 티어 기준**, 입장 시 1회 검사 |
| | 4티어: 1층 0명 / 2층 1명 / 3층 2명 / 4층 3명 |
| 파티 분배 | **시스템 개입 없음.** 가방은 공용 컨테이너, 선착순 |
| 크로스티어 킬 | **페널티 없음.** 억제는 파티 인원 제한이 담당 |

### 전투

| | |
| ---- | ---- |
| 인원 우위 | **보장한다.** 목표 — 고티어 1명 vs 저티어 4명 → **4명 승률 55~65%** |
| 소수 보호 장치 | 광역 쓸어담기 · 1인 캐리 — **의도적으로 억제** |
| 고독한 길 | 장비 계열. **1개만 착용해도 파티 영구 불가**, 착용 수만큼 시너지 |
| | 효과 배율 = f(내 티어 − 구역 티어). 같은 티어 100% → 3단계 아래 10% |
| | 목표 — 풀세트 1명 vs 동티어 일반 4명 → **솔로 승률 45~55%** |

#### CC 체계 (2026-08-11 전면 개정)

> **⚠️ "CC 점감 없음" 규칙은 폐지되었다.** CC 저항력 스탯으로 대체한다.

**하드 CC** — 플레이어가 조작을 못 하는 것 (기절 · 속박 · 넉백 · 공중띄우기)

| | |
| ---- | ---- |
| 장착 부위 | **무기 전용.** 다른 부위에는 하드 CC가 붙지 않는다 |
| 결과 | **캐릭터당 하드 CC 스킬 1개** — 한 명이 연속으로 묶을 수 없다 |
| 4인 파티 목표 | 체인 CC 총 **5초** (개당 평균 1.25초) |

**소프트 CC** — 조작은 되지만 불리해지는 것 (이동 감속 · 회복 감소 · 공격 불가)

| | |
| ---- | ---- |
| 장착 부위 | **제한 없음.** 어느 부위에든 붙는다 |
| 중첩 규칙 | **최대값만 적용.** 합연산·곱연산 금지 |
| 감속 강도 | **"추격이 조금 더 쉬워진다" 수준.** ⚠️ 상한 % 미정 |

> **중첩을 최대값으로 강제하는 이유.** 합연산이면 4명 × 30% = 실질 정지가 되어
> 소프트 CC가 하드 CC로 변질된다. 방금 무기 부위 제한으로 막은 구멍이 옆으로 열린다.

> **참고 계산**: 감속 30% → 340 → 238 cm/s. 10 m 앞선 상대를 따라잡는 데 약 10초.

**CC 저항력** — 모든 전투 가능 오브젝트가 갖는 스탯

| 대상 | 저항력 |
| ---- | ---- |
| 플레이어 | **장비로 상승.** 기본값 0 |
| 일반 몬스터 | 플레이어와 동일 규칙 |
| **보스형 몬스터** | **등급에 따라 고정 저항.** 상위 보스일수록 높음 |

```
실효 CC 시간  =  기본 지속시간 × (1 − CC저항력)
```

> **P2와의 정합성**: 저항력이 장비에서 온다는 것은 "힘은 손에 든 것에서만"과 일치한다.
> **P1과의 정합성**: 4명도 각자 저항 장비를 낄 수 있으므로 대칭적이다. 소수 전용 보정이 아니다.

> 🔴 **미해결 — 완전 면역 구멍** (2026-08-11 계승 분석에서 발견).
> `1 − CC저항력` 선형 형태는 **저항력이 1.0에 도달하면 완전 면역**이 된다.
> 아카이브 전투 GDD의 데미지 완화는 `armor / (armor + K)` **점근 곡선**이었고,
> 설계 근거에 **"완전 무적 불가"를 명시적 목표**로 적어두었다. CC 저항력만 선형이면
> **P1("숫자가 곧 힘")과 정면 충돌**한다 — 저항 100%를 맞춘 1명은 다구대일에 면역이 된다.
>
> **정식 Formula로 등재하기 전에 셋 중 하나를 정해야 한다.**
> ① 상한 클램프 (예: 최대 75%) ② 점근 곡선 채택 (`resist / (resist + K)`) ③ 선형 유지 + 장비 부여량 제한
> 소유: `systems-designer` · 시점: **전투 시스템 GDD 작성 전**

#### ⚠️ 알려진 한계 — 5초는 상한이 아니다

무기 부위 제한은 **캐릭터당 하드 CC 개수**를 막지, **인원수**를 막지 않는다.

| 인원 | 하드 CC 총 시간 |
| ---- | ---- |
| 4명 | 5초 |
| **8명** | **10초** |

**"5초"는 4인 기준 설계 목표값이며 하드 캡이 아니다** (2026-08-11 결정, 선택지 A).
진짜 상한을 만들려면 "하드 CC 적중 후 N초 면역"이 필요한데, 이는 **P1과 정면 충돌**하므로 채택하지 않았다.

> **파티 인원 제한을 우회하는 담합**(4인 파티 2개가 1명을 협공)은 **운영 대응 영역**으로 둔다.
> 시스템으로 막지 않는다 — P3와 일치한다.

### 탈출 · 압박

```
[입장]  진입 포인트는 매 세션 랜덤 · 진입 직후 3초 무적
        개인별 30분 타이머 시작

[탈출 타워]  개활지에 여러 개 · 원거리에서 실루엣으로 보임
  1. 구역 진입 → 게이지 시작 (인원 무관 60초 고정)
  2. 반경 N미터 내 플레이어에게 알림 — 방향·위치 비공개
  3. 구역 이탈 시 게이지 역행 / 1명이라도 남으면 계속 충전
  4. 방해 = 기존 스킬로만 (넉백·처치). 전용 방해 수단 없음
  5. 완충 → 구역 안 모든 플레이어 탈출 (적 포함)

[타이머 만료]  자동 사망 → 소지품 전량 소멸 (가방 드랍 없음)
               골드만 30% 유지, 나머지 70%도 소멸
```

### 🔴 두 종류의 죽음 — 결과가 다르다 (2026-08-11)

| | PvP · 몬스터에 의한 사망 | **타이머 만료 사망** |
| ---- | ---- | ---- |
| 소지품 | 가방으로 드랍 → **10분간 루팅 가능** | **전량 소멸.** 아무도 못 줍는다 |
| 골드 | 30% 유지 / **70% 가방에 드랍** | 30% 유지 / **70% 소멸** |
| 담당하는 것 | **회수 판타지** ("그놈이 아직 들고 있다") | **인플레 억제** (확정적 싱크) |

> **왜 나눴나.** 이전 설계는 "10분 뒤 소멸" 하나로 상충하는 두 목표를 동시에 떠받쳤다.
> 리텐션 훅("잃은 것 되찾기")은 **높은 회수율**을 원하고, 등급 아이템 인플레 억제는
> **낮은 회수율**을 원한다. 같은 손잡이로 정반대를 요구했다.
>
> **손잡이를 둘로 나눴다.** PvP 킬은 회수 가능하게, 타이머 만료는 확정 소멸로.
> 이제 각 목표가 독립적으로 튜닝된다.

> **부수 효과 — 30분 타이머의 압박이 크게 올라간다.** 못 나가면 전부 증발이다.
> 이는 P5("얻는 순간 잃을 것이 생긴다")를 강화한다.

### 스폰 보호 — P5를 위반하지 않는 선

신규 유저가 진입 60초 만에 영문도 모르고 죽는 문제에 대한 **최소 조치**다.

| 조치 | 내용 |
| ---- | ---- |
| **랜덤 진입 포인트** | 매 세션 위치가 바뀐다. **입구 캠핑 자체가 불가능** |
| **3초 무적** | 진입 직후. **이동 또는 공격 시 즉시 해제** |

> ⚠️ **"진입 포인트 주변 PvP 금지 존"은 채택하지 않았다.** Anti-Pillar 정면 위반이며
> (*"안전한 축적 수단을 만들지 않는다 — 던전 내 PvP 금지 구역"*), 실제로 악용된다 —
> 아이템을 잔뜩 들고 진입 포인트로 도망가면 무적이 되어 **사실상 두 번째 탈출구**가 되고,
> "귀환로 매복"이라는 핵심 다이나믹이 죽는다.
>
> 위 두 조치는 **스폰킬만 차단**한다. 스폰킬은 "안전한 축적"이 아니라 "시작조차 못 함"이므로
> P5 위반이 아니다. **아이템을 들고 도망칠 안전지대는 생기지 않는다.**

| | |
| ---- | ---- |

#### 두 가지 탐지 수단의 역할 분담

레이더 반경 22.5 m는 280 m 맵의 **8%**다. 이것만으로는 탈출 타워를 찾을 수 없다.

| 수단 | 거리 | 역할 |
| ---- | ---- | ---- |
| **레이더** | 근거리 22.5 m | 파티원 · 상자 — **정밀 탐지** |
| **타워 실루엣** | 원거리 (시야 내) | 탈출 경로 — **방향 인지** |
| **랜드마크** | 원거리 | 구역 식별 · 방향 감각 |

> **이 분담으로 컨셉과 아트 바이블의 모순이 해소된다.**
> 이전: 컨셉 "타워 위치 비공개" ↔ 아트 바이블 "어디서든 보임 · 게이지 찰수록 밝아짐"
> 현재: **타워는 보인다. 게이지 진행 상황도 보인다. 다만 레이더에 잡히는 건 근거리뿐이다.**

> ⚠️ **랜드마크가 필수 요소로 승격되었다.** 미니맵이 없으므로
> 아트 바이블의 구역별 실루엣(민가 / 헛간 / 무너진 층 / 궁궐)이 장식이 아니라
> **유일한 방향 감각 수단**이다. `art-bible.md` §6 참조.

| **Room 구조** | **층 1개 = Room 1개** |
| **동접 목표** | 층당 30명 (총 120) |
| **권위 모델** | **서버 권위 + 클라이언트 예측** — 아래 참조 |

### 권위 모델 (2026-08-11 확정)

**리그 오브 레전드 방식을 차용한다.**

```
클라  →  이동 입력 즉시 화면에 반영 (예측)  →  좌표를 서버에 전송
서버  →  검증:  Δ거리 ÷ Δ시간  ≤  340 cm/s × 1.15
           통과 → 브로드캐스트
           실패 → 거부 + 스냅백
```

> ⚠️ **"LoL은 클라 권위"는 오해다.** LoL은 완전한 서버 권위이며, 클라가 하는 것은 **예측**이다.
> 위치의 진실은 항상 서버가 갖는다. LoL에서 위치 핵이 통하지 않는 이유다.

**현재 코드는 이 모델이 아니다.** 클라가 보낸 좌표를 서버가 그대로 신뢰하며 **검증이 0줄**이다
(`ServerPacketHandler.cpp:83` TODO). 풀루팅 PvP에서 순간이동 강탈이 가능하다는 뜻이다.

§ 공간에서 이동속도 상수(340)가 확정되었으므로 **속도 상한 검증은 지금 구현 가능하다.**

> **LoL의 대표적 치트가 맵핵인 이유**는 서버가 시야 밖 정보까지 보내기 때문이다.
> MVP 계획인 **클라이언트 FoW가 정확히 같은 구멍**이다. 아래 FoW 표 참조.

### 30명 — 부하 관점에서 성립한다

**인원을 100 → 30으로 낮추면서 기술 리스크 두 개가 통째로 내려갔다.**

| 항목 | 100명 (이전) | **30명 (확정)** |
| ---- | ---- | ---- |
| 클라 수신 대역폭 | 634 kbps | **186 kbps** |
| 서버 업로드 | 63 Mbps | **5.6 Mbps** |
| 초당 `Send()` 호출 | 약 198,000 | **17,400** |
| 서버 메모리 (총 동접) | 400명 → 256 MB | **120명 → 77 MB** |
| **거리 기반 컬링(AOI)** | **필수** | **선택 — 최적화 항목으로 강등** |
| **DummyClient 하네스** | 필수 | 있으면 좋음 |

> ⚠️ **AOI를 "안 만들어도 된다"는 뜻은 아니다.** 30명 전원 상호 가시라도 단일 스레드가 감당하지만,
> 대역폭·CPU 여유가 커져 **12주 일정 밖으로 미뤄도 안전하다**는 뜻이다.
> `Room::Broadcast`는 여전히 거리 필터가 없다(구현 0줄).

- **방 단위 PVS** — 집(방+복도)에 적용. Tier 3. **이제는 성능이 아니라 P4(정보 은닉)가 이유다**
- **층 크기 280 m** — 균등 분포 시 동시 가시 약 1.9명. 교전은 집에서 일어난다 (§ 공간)

#### 대역폭 재계산 필요 (여전히)

`186 kbps` 수치는 **플레이어 위치 패킷만** 계산한 것이다. 다음이 누락되어 있다.

- 몬스터 위치 동기화 · 전투 패킷(스킬·데미지·CC) · 아이템 이벤트(스폰·루팅·소멸)

30명이라 여유가 크지만 **숫자 자체는 정확하지 않다.** `network-programmer` 재계산 필요.

### 스레드 모델 — 현재 상태 (2026-08-11 코드 확인)

| 항목 | 실제 |
| ---- | ---- |
| 워커 스레드 | **5개** (`GameServer.cpp:47`) |
| Room | **`class Room : public JobQueue`** — **JobQueue 전환 이미 완료** |
| 패킷 핸들러 | 전부 `GRoom->DoAsync(...)` 경유 |

> 🔴 **`LockQueue::PopAll`의 자기 재귀 락 수정이 아직 빌드 검증되지 않았다.**
> JobQueue가 **이미 라이브**이므로 이것은 잠복 버그가 아니라
> **접속 · 이동 · 퇴장 패킷 전부가 지나가는 활성 경로**다. 최우선 처리 대상.

#### ⚠️ Room 분할과 JobQueue가 무엇을 푸는지 정확히 알 것

이전 문서는 이 둘을 "층당 100명"의 해법으로 적었으나 **틀렸다.**

- **Room 4분할**은 층 인원 문제에 적용 불가다. "층당 N명"은 애초에 *하나의 Room 안* 인원이므로,
  Room을 4개로 늘려도 **한 Room이 담당하는 부하는 그대로**다. Room 분할이 푸는 것은
  **여러 층이 동시에 돌아갈 때의 병렬성**이지 한 층의 부하가 아니다.
- **JobQueue**는 설계상 한 Room을 **항상 단일 스레드**로 실행한다. 락을 없애는 것이지
  팬아웃을 없애는 것이 아니다.

```
30명 × 20 Hz × 29명 팬아웃  ≈  초당 17,400회 Send()  — 단일 스레드로 충분
```

**30명에서는 단일 스레드 팬아웃이 병목이 아니다.** 100명이었다면 초당 198,000회로
컬링 없이는 성립하지 않았을 것이다. **인원 축소가 이 문제를 없앴다.**

거리 컬링은 여전히 미구현이지만, 이제 **성능 필수 요건이 아니라 최적화 항목**이다.

> 드랍률 조정으로는 풀리지 않는다 — 층 하한선·저층 스탯 정규화·세션당 입장 제한 등 구조적 답이 필요하다.

## MVP Definition

**검증 질문: "들고 나가는 결정이 실제로 갈등을 유발하는가?"**

### 일정 (2026-08-11 확정 — 14주)

| 작업 | 주 | 변경 |
| ---- | ---- | ---- |
| **P0 넷코드 + 계측/테스트 인프라** | **2** | 🆕 1 → 2. **계측 훅·GoogleTest·DummyClient 봇이 원안에 없었다.** 없으면 어떤 게이트도 판정 불가 |
| P1 전투 — 평타 · 데미지 · 사망 · CC | 3 | 유지 |
| **P1.5 스킬 + 장비-스킬 결속** ⭐ | **1** | 🆕 **신규. USP.** 6슬롯 구조 + 스킬 2~3종 |
| P2 아이템 · 인벤토리 · 드랍 · 가방 · 세이브 | 2 | 강화 제외 |
| P3 몬스터 AI + 1층 · 집 3개 | **3** | AI 1 + 레벨 2 통합 |
| P4 탈출 타워 + 게이지 | 1 | 유지 |
| **P5 통합 · 디버깅 · 플레이테스트** | **2** | **절대 축소 금지 — 지켜짐** |
| **합계** | **14주** | **11-17 완료.** 발표(11-21)까지 4일 |

> **절삭은 하지 않았다.** 대신 **데모 준비 2.6주를 포기**해 14주 전체를 개발에 썼다 (2026-08-11 결정).
> 발표 완성도보다 개발 진도를 택한 **의식적 트레이드오프**다.
> 유일한 보험은 **11-16 시연 녹화본**(30분). 상세는 `production/roadmap.md` §8.

**Tier 2로 연기**: AOI / 거리 컬링 · FoW
🔴 **DummyClient 하네스는 최소판을 MVP로 당긴다** — 없으면 SV-1·2·5·6 네 게이트를 **전부 측정할 수 없다.**
접속 유지 + 이동 패킷만 흘리는 최소판(약 1일)이면 충분하다. 완전판은 Tier 2.
→ **MVP는 소수 클라이언트로 검증**한다. 3명에게 컬링과 부하 하네스는 무의미하다.

### 절삭 순서 (일정이 밀릴 때)

일정이 밀렸을 때 급하게 판단하지 않기 위해 **미리 확정한다.**

> **잘린다고 사라지는 게 아니다.** 2026-11-21은 프로젝트 종료일이 아니라 **성과 시연일**이다.
> 발표 후에도 개발은 계속되므로, 절삭은 **"안 만든다"가 아니라 "발표 후 순번으로 민다"** 는 뜻이다.
> 발표 목표는 "전부 완성"이 아니라 **"돌아가는 것을 최대한 많이 보여준다"** 이다.

```
마지막까지 지킴 ─┬─ 넷코드 (기반)
                 ├─ 전투
                 ├─ 아이템 드랍 · 루팅
                 └─ 탈출 게이지
                        ↓ 자를 수 있음
                   레벨 — 집 1개만 남기고 개활지 축소
                        ↓
                   몬스터 AI — 추격만, 스킬 없음
                        ↓
                   통합 플레이테스트 축소 (⚠️ 0으로는 절대 안 됨)
```

### 검증 기준 (Pass / Fail)

> "재밌나?"는 pass/fail을 낼 수 없다. 아래로 대체한다.

**측정 시점**: 11주차 통합·플레이테스트 기간
**측정 방법**: 외부 플레이테스터 8명 이상 × 1인 3세션 이상

**Pass — 3개 중 2개 이상 충족**

| # | 지표 | 기준 |
| ---- | ---- | ---- |
| 1 | **망설임** — 탈출 구역 진입 후 이탈(게이지 역행)이 발생한 세션 비율 | ≥ 30% |
| 2 | **리스크 감수** — 사망 시 소지 아이템 등급이 본인 세션 평균보다 높았던 비율 | ≥ 40% |
| 3 | **설문** — "나갈지 더 할지 고민한 정도" 1~5점 | 평균 ≥ 3.5 |

⚠️ 수치는 초안이다. `game-designer`가 전투 프로토타입 이후 확정한다.
1·2번은 **텔레메트리로 자동 집계 가능**해야 한다 — 1인 개발에서 주관적 인상만으로는 재현성이 없다.

**Fail 시**: Tier 2 착수 보류. 재설계 논의.

### MVP 무대 — **1층 (평민 민가)**

에셋이 가장 싸고(초가·담장·우물·마차), 서사의 시작점이며, 아트 바이블 Section 6의
1구역 규칙이 이미 확정되어 있다. **집 3개 중 하나에 "집 보스"를 배치**해 전투 검증을 확보한다.

**포함**: 1층 개활지 + 집 3개 · 상자 파밍 · 몬스터 · PvP(전원 적대) · 가방 드랍 · 탈출 게이지 · 30분 타이머 · 아이템 등급 · **근거리 레이더** · **서버 이동 검증** · **랜덤 진입 + 3초 무적**
**제외**: 파티 · 층 2~4 · 티어 게이팅 · 강화 · 고독한 길 세트 · 경제 · **FoW 전체** · **AOI/거리 컬링** · **DummyClient 하네스**

> 파티가 없어도 "죽이고 뺏고 도망친다"는 성립한다. 초기 검증에는 오히려 이쪽이 낫다 — 클라이언트 3개로 *한 명이 털고 → 다른 놈이 죽이고 → 가방 뺏어 탈출* 을 전부 재현할 수 있다.

### MVP에서 실제로 검증되는 것

체크마크에는 **무엇이 관찰되면 참인지**를 붙인다. 근거 없는 ✅는 쓰지 않는다.

| Pillar | MVP | 관찰 가능한 근거 |
| ---- | ---- | ---- |
| **P2** 힘은 손에 든 것에서만 | ✅ | 세션 시작~종료 캐릭터 기본 스탯 불변 + 장비 교체 시 공격력 즉시 변경 — 자동 테스트 |
| **P5** 얻는 순간 잃을 것이 생긴다 | ✅ | 사망 시 인벤토리 슬롯 100%가 가방으로 전이 + 캐릭터 인벤 0 — 통합 테스트 |
| **P4** 정보가 가장 비싼 자원 | **⚠️부분** | **하향 조정.** 레이더에 적이 안 뜨는 것은 확인 가능하나, **FoW가 MVP에서 제외**되어 서버 측 정보 은닉은 미검증. 월핵 방지는 Tier 3 PVS 이후 |
| **P1** 숫자가 곧 힘이다 | ⚠️부분 | 3인 이상이 한 대상을 동시 공격할 때 TTK가 1:1 대비 유의미하게 감소함을 로그로 확인. **파티 UI가 없어 승률 목표(55~65%)는 측정 불가** |
| **P3** 시스템은 처벌하지 않는다 | ⚠️부분 | 킬·루팅 시 서버 로그에 페널티성 이벤트 미기록 = 학살·닌자루팅 무처벌은 검증 가능. **"배신"은 파티가 없어 검증 불가** |

> ⚠️ **아세틱 기준으로도 확인할 것.** MDA 2순위인 **Fellowship**은 파티가 Tier 2이므로
> MVP에서 실질 검증되지 않는다. **MVP는 6개 아세틱 중 4~5개만 검증한다.**
