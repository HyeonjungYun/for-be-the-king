## Section 1: Visual Identity Statement

> **Status**: ✅ Locked — 2026-08-10

### 한 줄 비주얼 규칙

> # **"읽히지 않으면 존재하지 않는다"**

모든 시각적 판단의 최종 기준. 아무리 멋있어도 **탑다운 거리에서 1초 안에 판독되지 않으면 그 요소는 실패**다.

이 규칙이 최우선인 이유는 P4(정보가 가장 비싼 자원) 때문이다. 층당 30명이 공존하고, 위치·의도·상태를 읽어내는 것이 곧 실력인 게임이다. 화면이 읽히지 않으면 게임의 핵심 재미가 성립하지 않는다.

---

### 보조 원칙

#### ① 납작하게, 그러나 또렷하게

디테일은 텍스처가 아니라 **실루엣과 색면**으로 표현한다. 로우폴리 + 플랫/셀 셰이딩.
노멀맵으로 표현해야 할 수준의 디테일이라면 **애초에 넣지 않는다.**

| | |
|---|---|
| **설계 테스트** | 텍스처 디테일 추가 vs 실루엣 변경 중 고민되면 → **실루엣을 바꾼다** |
| **섬기는 필러** | P4 — 정보가 가장 비싼 자원 |
| **부수 효과** | 에셋 제작비가 크게 낮아짐. 1인 개발 + 199만원 예산에서 사실상 필수 조건 |

> 탑다운 pitch −60°에서 캐릭터는 화면상 작게 보인다. 미세 텍스처는 **보이지 않는 데 메모리만 쓴다.**

#### ② 귀여운 껍질, 잔혹한 속

캐릭터와 월드는 친근하되, **손실의 순간만은 무겁게** 연출한다. 톤의 낙차 자체가 이 게임의 개성이다.

| | |
|---|---|
| **설계 테스트** | 죽음·강탈 연출이 "귀엽게 넘길까 무겁게 갈까" 고민되면 → **무겁게.** 단 유혈이 아니라 **정적·여백·색 빠짐**으로 |
| **섬기는 필러** | P5 — 얻는 순간 잃을 것이 생긴다 |

> 타르코프의 암울한 톤은 진입 장벽이다. 귀여운 외피는 전손의 고통을 견딜 만하게 만들어
> **더 많은 플레이어가 하드코어 규칙을 시도하게** 한다. 덕코프가 증명한 접근.

#### ③ 화려함은 정보에 양보한다

이펙트·조명·포스트프로세스가 게임플레이 정보를 가리는 순간 **삭제 대상**이다. 예외 없다.

| | |
|---|---|
| **설계 테스트** | 이펙트가 멋있는데 캐릭터를 가린다면 → **삭제하거나 투명도를 올린다** |
| **섬기는 필러** | P4, 그리고 P1 — 4명이 1명을 둘러싸도 **그 1명이 보여야** 인원 우위가 성립한다 |

> 구체적 금지 후보: 화면 전체 블룸 과다, 짙은 색수차, 캐릭터를 덮는 불투명 파티클,
> 강한 모션 블러. 상세는 Section 7·9에서 확정.

#### ④ 양식 — 건축은 조선 형태, 색은 조선이 아니다 `[2026-08-20 개정]`

> 🔴 **2026-08-17 초판은 "양식 전반이 조선풍"이었다. 이는 잘못이다.**
> 실제 방향은 아래와 같다.

**양식은 위 세 원칙에 종속된다.** 고증이 판독성과 충돌하면 판독성이 이긴다.

| 영역 | 방향 | 탑다운 판정 |
|---|---|---|
| **건축 — 형태** | 🔴 **조선 차용.** 한옥 칸 구조 · 처마 · 용마루 · 공포 | ✅ 강한 수평선. "배경은 수평" 규칙과 그대로 맞는다 |
| **건축 — 색** | 🔴 **조선 색을 쓰지 않는다.** 단청 원색 제외 | ✅ 배경 저채도 유지 — 원칙 ③과 충돌 없음 |
| **인물 · 의복** | **혼합** — 조선 계열을 포함하되 한정하지 않는다 | 실루엣 규칙(§3 ①)만 지키면 자유 |
| **무기** | **혼합** | ✅ **오히려 유리** — §3 ② 참조 |
| **스킬 연출 · 색** | **자유롭게 다채롭게** | ✅ 배경이 저채도라 충돌하지 않는다 |

##### ✅ 단청 충돌이 해소되었다

초판은 단청을 **"유일한 충돌 지점"** 으로 지목하고 깊이별 배분(1층 없음 → 4층 사용)으로
해결하려 했다. **건축 색에서 단청 원색을 빼기로 하면서 이 문제 자체가 사라진다.**

```
초판   단청(고채도 배경)  vs  전리품·타워(히어로 색)          → 충돌, 깊이 배분으로 완화
현재   저채도 배경        vs  전리품·타워  vs  스킬 6종 색    → 충돌 없음
```

**대신 스킬 색이 자유로워졌다.** 배경이 채도를 양보했으므로 히어로 요소가 색을 독점한다 —
이것이 원칙 ③(화려함은 정보에 양보)의 원래 의도다.

> 💡 **단청 문양은 색이 아니라 형태로 남길 수 있다.** 저채도 단색으로 단청 문양을 새기면
> 궁궐의 시각 정체성은 유지되면서 채도 경쟁은 일어나지 않는다.
> **`worldbuilding.md` § 3.2 의 "지하에 뒤집힌 채 박힌 단청 기둥" 이미지가 이 방식으로
> 살아남는다** — 색이 아니라 **부서진 공포와 뒤집힌 처마의 형태**가 궁궐임을 말한다.

> 🔴 **4층 궁궐을 만들 때 재확인할 것**: 단청 없이 궁궐로 읽히는가.
> 읽히지 않으면 **색을 되살리는 것이 아니라 형태 밀도(공포·다포·처마 곡선)를 올린다.**

##### 왕가 문양 규칙

곤룡포 계열의 자수는 **용이 아니라 마법진**이다 (`worldbuilding.md` § 3.1).
MVP 에는 왕가 복식이 등장하지 않으므로 기록만 해 둔다.

## Section 2: Mood & Atmosphere

> **Status**: ✅ Locked — 2026-08-10

게임 상태별 감정 목표. 조명 아티스트가 바로 작업할 수 있는 수준으로 명시한다.

**코어 루프 기준 상태**
```
베이스캠프 → 개활지 → 집 → 귀환로 → 탈출 게이지 → (성공 or 사망)
```

---

### ① 베이스캠프 — *유일하게 안전한 곳*

| | |
|---|---|
| **감정 목표** | 안도, 그러나 지루하지 않은 재정비의 긴장 |
| **조명** | 따뜻함 **2800~3200K**. 횃불·화롯불. 부드러운 그림자, **낮은 대비** |
| **분위기 형용사** | 아늑한 · 북적이는 · 임시적인 · 어수선한 |
| **에너지** | 낮음 — 유일하게 숨 돌리는 구간 |
| **무드 캐리어** | 화로의 흔들리는 불빛. 던전 입구를 향한 시선 유도 |

> 게임 전체에서 **유일한 따뜻한 색 온도**다. 이 대비가 던전을 더 차갑게 만든다.

### ② 개활지 — *노출된 이동*

| | |
|---|---|
| **감정 목표** | 경계. "누가 보고 있을지도 모른다" |
| **조명** | 서늘한 중성 **5000~6000K**. 균일하고 **그림자가 얕음** — 숨을 곳이 적다는 신호 |
| **분위기 형용사** | 트인 · 조용한 · 무방비한 · 넓은 |
| **에너지** | 중간 — 이동은 계속되지만 사건은 드묾 |
| **무드 캐리어** | 넓은 시야와 긴 사선. 멀리 보이는 실루엣 하나가 곧 정보 |

### ③ 집 — *탐욕의 방*

| | |
|---|---|
| **감정 목표** | 탐욕과 공포의 동시 상승 |
| **조명** | **강한 대비.** 어두운 복도 + 국소 조명이 상자·전리품을 스팟처럼 비춤. 차가운 그림자 |
| **분위기 형용사** | 밀폐된 · 유혹적인 · 매복 가능한 · 값진 |
| **에너지** | 최고 — 몬스터·타 플레이어·전리품이 한 곳에 |
| **무드 캐리어** | **빛이 곧 가치.** 밝은 지점 = 상자, 어두운 지점 = 위험 |

> 조명이 게임플레이 신호다. *"저기 밝다 = 아직 안 털렸다."*
> 리스폰 30분 · 집별 독립 타이머와 맞물려, **빈 집은 어둡게** 보이도록 연출할 수 있다.

### ④ 귀환로 — *가장 위험한 순간*

| | |
|---|---|
| **감정 목표** | 초조. 들고 있는 게 많을수록 무거워지는 발걸음 |
| **조명** | 개활지와 동일하되 **채도를 낮춤** |
| **분위기 형용사** | 노출된 · 급한 · 되돌아갈 수 없는 |
| **에너지** | 높음 — 전투는 없어도 심박은 최고 |
| **무드 캐리어** | 체류 타이머 UI. 멀리 보이는 탈출 타워 |

> ②와 물리적으로 같은 공간이지만 감정은 정반대(경계 ↔ 초조)다.
> **구분 수단은 채도뿐이다.** 시간 경과 조명 연출은 **검토 후 비채택** (2026-08-10).

### ⑤ 탈출 게이지 60초 — *버티는 시간*

| | |
|---|---|
| **감정 목표** | 응축된 긴장. 시간이 느리게 가는 감각 |
| **조명** | 타워 중심의 **국소 발광이 60초에 걸쳐 서서히 강해짐** |
| **분위기 형용사** | 집중된 · 노출된 · 임박한 |
| **에너지** | 최고 |
| **무드 캐리어** | **게이지 자체가 조명.** 차오를수록 타워가 밝아짐 → 멀리서도 보임 = 어그로 |

> 게이지 진행 = 광량이면, 별도 UI 없이도 습격자가 남은 시간을 읽는다. P4에 부합.
> 탈출 알림이 "반경 N미터 · 방향 비공개"인 것과 결합해, **빛이 유일한 방향 단서**가 된다.

### ⑥ 사망 — *색이 빠진다*

| | |
|---|---|
| **감정 목표** | 상실. 분노가 아니라 **정적** |
| **연출** | **채도 급감 + 시간 감속 + 소리 뭉개짐.** 유혈 없음 |
| **분위기 형용사** | 조용한 · 멈춘 · 비어 있는 |
| **에너지** | 0 — 의도적 정지 |
| **무드 캐리어** | 내가 흘린 가방이 그 자리에 남아 있는 컷 |

> **원칙 ②(귀여운 껍질, 잔혹한 속)의 실행 지점.**
> 귀여운 캐릭터가 죽지만 연출은 무겁게. 유혈 대신 **색이 빠지는 것**으로 처리한다.

## Section 3: Shape Language

> **Status**: ✅ Locked — 2026-08-10

탑다운에서 **여러 명이 겹칠 때 서로를 구분하게 만드는 기하학적 규칙**.

---

### ① 캐릭터 실루엣 — 썸네일 판독성

탑다운 pitch −60°에서 얼굴은 거의 보이지 않는다. **위에서 본 형태만 보인다.**

| 규칙 | 내용 |
|---|---|
| **판독 단위는 어깨선과 머리** | 위에서 보이는 건 사실상 이 둘. 정보를 여기 몰아넣는다 |
| **장비가 실루엣을 바꾼다** | **P2 실행 지점.** 투구·어깨보호구·망토가 위에서 보이는 외곽선을 바꿔야 한다. 흉갑처럼 위에서 안 보이는 부위는 시각적 비중을 낮춘다 |
| **썸네일 테스트** | 캐릭터를 **32×32 픽셀**로 줄여도 무기 계열이 구분되면 통과 |

**복식은 혼합이다 — 실루엣 규칙이 양식에 우선한다** `[2026-08-20 개정]`

> 🔴 **초판은 "조선 복식이 이 규칙에 그대로 올라탄다"였다.** 복식은 조선에 한정하지
> 않고 혼합한다(§1 ④). **판독 단위는 여전히 머리쓰개와 어깨선**이며, 어느 문화권의
> 옷이든 그 둘을 만족해야 한다.

| 계층 | 위에서 본 **형태** (양식 무관) | 판독 |
|---|---|---|
| 하급 | 맨머리 또는 작은 머리쓰개 · 몸에 붙는 상의 | 작고 단순한 타원 |
| 상급 | 넓은 소매 또는 어깨 구조물 | 어깨 폭이 넓은 사다리꼴 |
| 최상급 | **머리 위 원반** | 머리 위가 통째로 커진 실루엣 |

**조선 계열 구현 예시** (한정이 아니라 예시다)

| 계층 | 조선 |
|---|---|
| 하급 | 수건 · 짧은 저고리 |
| 상급 | 철릭 · 답호 |
| 최상급 | **갓** |

> **머리 위 원반이 이 게임 최고의 탑다운 자산이다.** 챙이 수평으로 뻗은 형태는 위에서 볼 때
> 가장 크고 단순하다. **갓은 그 구현 중 하나**이며, 후드·챙모자·관·투구로도 같은 실루엣을
> 만들 수 있다 — **원칙은 형태이고 갓은 예시다.**
>
> ⚠️ 단 **원반이 어깨선을 덮어 가린다.** 이런 머리쓰개를 쓴 캐릭터는 어깨 정보가 죽으므로,
> 장비 실루엣을 **머리쓰개 자체의 형태 변화**(챙 폭 · 끈 · 상단 장식)로 옮겨야 한다.

### ② 무기 = 실루엣의 주역

장비=스킬 시스템이므로 **손에 든 것이 곧 그 플레이어의 정체성**이다.

```
짧은 굽은 선     환도 · 시미터
긴 직선          창 · 직검(길이로 창과 구분)
깊게 굽은 호     각궁 · 장궁
긴 선 + 밝은 점  지팡이 · 완드
각진 덩어리      도끼 · 망치
큰 면            방패
```

**무기는 캐릭터 몸통보다 과장한다.** 실제 비율보다 크게 — 탑다운에서 읽히려면 필요하다.
덕코프의 "작은 오리 + 큰 총" 실루엣과 같은 접근. 과장이 오히려 아기자기함을 강화한다.

> ✅ **혼합이 형태 어휘를 넓힌다** `[2026-08-20 개정]`
>
> 초판은 조선 무기 한정이라 **환도와 각궁이 둘 다 "굽은 것"** 이 되어 겹치는 문제를
> 지적하고 길이로 갈라야 한다고 적었다. **무기를 혼합하면 그 제약이 풀린다.**
>
> ```
> 조선 한정   굽은 선 · 깊게 굽은 호 · 직선 · 면            ← 앞 둘이 겹침
> 혼합        굽은 선 · 호 · 직선 · 각진 덩어리 · 면 · 봉   ← 전부 갈림
> ```
>
> **형태 축이 6개로 벌어져 32×32 썸네일 테스트가 훨씬 쉬워진다.**
> 다만 같은 축 안에서는 여전히 **길이·굵기로 갈라야 한다**(창 vs 직검, 환도 vs 시미터).

### ③ 환경 기하 — 각진 것이 지배한다

| 요소 | 형태 |
|---|---|
| **집(방+복도)** | **직각 중심.** 벽·문·복도가 명확한 격자. 방 단위 PVS 구현에도 유리 |
| **개활지** | 완만한 유기적 지형. 단 **엄폐물은 각지게** — 숨을 수 있는지 즉시 판단되어야 함 |
| **상자·전리품** | **작고 각진 형태 + 밝은 색.** 지형과 절대 섞이지 않게 |
| **탈출 타워** | **수직 랜드마크.** 층에서 유일하게 높이 솟은 것. 어디서든 보임 |

> 지배 형태는 **각(角)**. 로우폴리 + 각진 형태 = 실루엣이 단순하고 또렷해진다.

**조선 건축이 이 규칙과 맞는 지점** `[2026-08-17]`

| 요소 | 형태 기여 |
|---|---|
| 한옥 칸(間) 구조 | ✅ 기둥 간격이 일정한 **격자**. "직각 중심" 그대로 |
| 처마 · 용마루 | ✅ 강한 **수평선**. "배경은 수평" 규칙과 일치 |
| 마당(중정) | ✅ 벽으로 둘러싸인 개활 공간. 교전장으로 그대로 쓸 수 있다 |
| **기와의 반복 곡선** | ⚠️ 지붕면이 잔무늬로 시끄러워질 수 있다. **위에서 보이는 면이므로 특히 주의** |

> **던전의 결정적 이미지**는 정상적인 한옥이 아니라 **부서진 채 묻힌 한옥**이다 —
> 지하에 뒤집힌 채 박힌 기둥, 흙에 반쯤 묻힌 처마
> (`worldbuilding.md` § 3.2). 기울고 파묻힌 형태가 오히려 각을 만들어 준다.
>
> `[2026-08-20]` **색이 아니라 형태로 궁궐임을 말한다**(§1 ④). 단청 원색을 쓰지 않으므로
> 부서진 공포·다포·뒤집힌 처마의 **형태 밀도**가 그 역할을 대신한다. 단청 문양이 필요하면
> **저채도 단색으로 새긴다.**

> ⚠️ **기와 지붕면은 탑다운에서 화면의 상당 부분을 차지한다.** 실제 기와의 골을
> 그대로 재현하면 고주파 무늬가 되어 그 위의 캐릭터를 잡아먹는다.
> **면으로 단순화하고 골은 라이팅으로만 암시**하는 방향으로 Section 6 에서 확정할 것.

### ④ 히어로 형태 vs 배경 형태

| 계층 | 형태 규칙 |
|---|---|
| **히어로** (눈이 가야 함) | 플레이어 · 몬스터 · 전리품 · 타워 → **비대칭 · 밝음 · 각짐 · 수직** |
| **중간** | 엄폐물 · 문 · 상호작용물 → 각지되 채도 낮음 |
| **배경** (물러나야 함) | 지형 · 벽 · 장식 → **대칭 · 어두움 · 완만함 · 수평** |

> **가장 중요한 규칙**: 배경 요소는 절대 비대칭 실루엣을 갖지 않는다.
> **비대칭 = "여기 뭔가 있다"** 는 신호로 예약한다.

### ⑥ 월드 공간 마커

HUD와 별개로, **캐릭터 위에 붙는 마커** 계층.

| 마커 | 형태 | 가시 범위 |
|---|---|---|
| **배신자 표식** | 비대칭 · 각진 형태 · 고채도 | **배신당한 이전 파티원에게만** |
| 파티원 표시 | 대칭 · 부드러운 형태 · 저채도 | 파티원 전체 |
| 탈출 게이지 | 원형 진행바 | 타워 구역 내 전원 |

#### 배신자 표식 규칙

1. **로컬 전용** — 무관한 제3자에겐 보이지 않는다. 전역 낙인이 아니다
2. **한시적** — 일정 시간 후 사라진다 (지속 시간은 밸런싱)
3. **정보일 뿐** — 스탯 패널티 없음. 표식이 있다고 약해지지 않는다
4. **형태로 먼저 읽히게** — 색만으로 구분하지 않는다 (색맹 대응, Section 4)

> **P3와 충돌하지 않는 이유**: P3가 금지하는 것은 **처벌**(스탯 패널티 · 평판 하락 · 바운티)이다.
> 표식은 처벌이 아니라 **정보**이며, 배신당한 사람에게만 주어지므로 오히려 **P4에 부합**한다.
> 시스템이 벌하는 게 아니라 **응징할 수단을 주는** 것이다.
> 성기사 "배신자 처단" 시그니처는 대상 지정이 필요하므로, 표식 없이는 그 스킬이 성립하지 않는다.

> **형태 언어상 배신자 표식은 "히어로 계층"** 이다(비대칭 · 밝음 · 각짐).
> 난전 중 즉시 찾아야 하기 때문. 단 **드물어야 가치가 있다** — 남발되면 배경 노이즈가 된다.

> **구현 시점**: 배신 시스템은 **Tier 2 (2026-12-31)**. MVP에는 파티가 없으므로 표식도 그때 들어간다.
> 다만 형태 언어는 지금 고정한다 — 나중에 급조하면 계층 규칙이 흐트러진다.

### ② 아이템 등급 — 4단계, 색 + 형태 이중 부호화

> **핵심 발견**: 여러 조합을 검증한 결과 **4색 이상을 색만으로 구분하는 것은 불가능**하다.
> 따라서 **형태가 주 신호, 색이 보조**다.

| 등급 | 색 | 형태 (외곽선) | 보조 효과 |
|---|---|---|---|
| **일반** | `#9AA0A6` 무채 | 직사각 | — |
| **희귀** | `#199E70` 청록 | 모서리 깎임 | — |
| **영웅** | `#3987E5` 파랑 | 육각 | 미세 발광 |
| **전설** | `#E66767` 적 | **별형** | 발광 + 파티클 |

**검증 결과**: 색맹 최악 ΔE **6.5** (WARN 구간) · 정상시야 최악 ΔE **15.2** (PASS)
→ WARN 구간은 "보조 부호화가 있을 때만 허용"이며, **형태를 필수 동반**하므로 조건 충족.

> **합격 기준**: 흑백 스크린샷으로 찍어도 등급이 읽혀야 한다.

4층 최희귀 장비      →  전설
```

### ③ 상태색 — ⚠️ 3색 동시 사용 불가

검증 결과 "위험=적 / 안전=녹 / 보상=금" 3색 동시 사용이 **불가능**하다.

금 #C98500 ↔ 적 #E66767    정상시야 ΔE 13.0   FAIL

**해결: 상태를 색으로 표현하지 않는다.**

| 상태 | 표현 방식 |
|---|---|
| **위험** (체력 감소) | **화면 가장자리 비네트**가 주 신호. 색(`#D03B3B`)은 보조 |

| **안전** | 색을 쓰지 않는다. **위험의 부재**로 표현 |

## Section 6: Environment Design Language

> **Status**: ✅ Locked — 2026-08-10

---

### ① 세계관 — 함몰된 고대 왕국

대륙 정중앙에 있던 **고대 왕국이 지반 함몰로 통째로 가라앉았다.** 그 자리에 던전이 생겼다.

- **깔때기 구조** — 왕국 중심부일수록 깊이 떨어졌다
- 건물들은 낙하 중 부서져 **대부분 한 층만** 남았다
- 완전한 폐허는 아니다. 형태는 알아볼 수 있다 (P4 — 길이 읽혀야 함)

#### 이 설정이 푸는 문제 3가지

**1. 깊이 = 사회적 계층 = 서사**
```
지상 ─────────────────────  대륙
  1층   민가              평민
  2층   궁궐 외곽시설      하인 · 병사
  3층   낙하한 궁궐 파편   귀족
  4층   궁궐              왕
```
게임 제목이 **"For be the King"** 이다. 4층 도달 = 왕좌 도달. 티어 게이팅이 난이도 구분이 아니라 **서사**가 된다.

**2. "모든 집이 단층"이 정당화된다**

탑다운에서 다층 건물은 최악이다 — 2층이 1층을 가린다. 보통은 억지 제약을 걸어야 하는데,
**낙하 중 부서져 한 층만 남았다**는 설정으로 **게임플레이 요구와 세계관이 일치**한다.

**3. 함몰 물리가 계층 배치를 설명한다**

왕국 중심(궁궐)이 가장 깊이 떨어지고 외곽 민가는 얕게 내려앉았다.
→ **깊이 = 원래 왕국에서의 중심도.** 물리적으로도 서사적으로도 성립.

---

### ② 층별 건축 — 같은 문법, 다른 계층

**역층 구조다 — 1층이 가장 얕고 4층이 가장 깊다.** 모든 층은 기본적으로 **동굴**이며,
그 안에 개활지와 통로가 있고 건물 잔해가 흩어져 있다.

| 층 | 건축 유형 | 개활지 | 재료 | 색온도 |
|---|---|---|---|---|
| **1층** | **평민 민가** — 단층 목조·흙벽. 부엌, 침실 | 무너진 마을 외곽, 흙과 잔해 | 흙 · 나무 · 거친 돌 | 5000K 중성 |
| **2층** | **궁궐 외곽시설** — 헛간, 주방, 창고, 병영 | 궁궐 마당·정원의 잔해 | 다듬은 석재 · 목재 | 5500K 옅은 청 |
| **3층** | **낙하한 궁궐 파편** — 궁궐 한 층이 통째로 떨어져 홀로 박혀 있음 | 구조물 파편이 흩어진 지대 | 대리석 · 금속 | 6000K 청 |
| **4층** | 🔴 **왕의 사적 공간** — 침소, 집무실. **온전히 보존되어 있다** | 궁궐 대광장 | 흑요석 · 귀금속 | 6500K 차가운 청보라 |

> **3층이 시각적으로 가장 극적이다.** 궁궐 한 층이 통째로 기울어진 채 땅에 박힌 실루엣.
> 다른 층과 확연히 구분되고, *"위에 뭔가 더 있다"* 는 예감을 준다.

#### 🔴 파괴 상태 — 1~3층은 폐허, 4층만 멀쩡하다 `[2026-08-23 확정]`

| 층 | 상태 |
|---|---|
| **1~3층** | **온전한 건물이 하나도 없다.** 한쪽이 무너졌거나, 통째로 뒤집혔거나, 절반이 흙에 박혔다. 지붕만 남은 것, 벽 한 면만 선 것 |
| **4층** | **함몰 전 그대로다.** 문이 닫혀 있고 기와가 얹혀 있으며 기둥이 서 있다 |

이 대비가 4층 도달의 의미를 만든다. 수십 시간 동안 부서진 것만 보다가, 바닥에서 **처음으로
멀쩡한 건물**을 만난다. 그리고 그것이 왜 멀쩡한지가 곧 이 게임의 답이다.

> **왜 4층만 보존되었나** — 니라는 왕궁을 통째로 지하에 처넣으면서 **아버지의 공간만은
> 부수지 않았다.** 대륙을 지옥으로 만들고 자기를 적대한 자들을 그 안에 가둔 사람이,
> 침소 하나는 손대지 못했다. 그의 증오가 어디서 멈추는지를 보여주는 유일한 물증이며,
> `worldbuilding.md` § 8 의 **"명시하지 않는다"** 방침에 따라 아무도 이것을 설명해 주지 않는다.
> 플레이어가 눈으로 보고 스스로 알아차릴 뿐이다.

#### 공간 비중 — 건물 20 / 개활지 80 `[2026-08-23 확정]`

| | 비율 | 근거 |
|---|---|---|
| **건물·실내** | **20%** | 탐색과 매복. 밀도 높은 보상이 여기 있다 |
| **개활지·통로** | **80%** | 시야가 자원(P4). **빈 공간이 곧 긴장이다** |

> 이 비율이 § ④ 소품 밀도 규칙과 짝을 이룬다 — 넓은 곳은 비우고 좁은 곳은 채운다.
> 280m × 280m 에 건물 3~5개라는 MVP 수치도 여기서 나온다.

#### 🔴 MVP 무대 = **1층 (평민 민가)** — 2026-08-11 확정

MVP는 **1층 하나만** 만든다. 여기에만 에셋 예산을 쓴다.

> 서사적으로는 **길드가 설치한 것**이라 함몰 이전 건축과 양식이 다르다.
> 시대가 다른 물건이 섞여 있는 것이 자연스럽다.

### ⑧ 제작 전략 — 모듈 재사용

```

     ↓

```

건축 유형이 다르므로 **소품 세트는 층별로 필요**하지만, 구조 모듈은 재사용한다.

| 수단 | 거리 | 역할 |
|---|---|---|

| **타워 실루엣** (Section 3 ③) | 원거리 · 시야 내 | 탈출 경로 — 방향 인지 |
| **구역 랜드마크** (Section 6) | 원거리 | 구역 식별 · 방향 감각 |

> 🔴 **랜드마크가 장식에서 필수 시스템으로 승격되었다.**
> 미니맵이 없으므로 구역별 실루엣(민가 / 헛간 / 무너진 층 / 궁궐)이
> **플레이어의 유일한 방향 감각 수단**이다. Section 6의 실루엣 차별화는 이제 타협 불가다.

이것이 만드는 것:
- **층 지리 학습이 실력이 된다** — 컨셉의 장기 성장 요소와 부합
- **적을 찾으려면 직접 봐야 한다** — P4의 핵심 실행 장치
- **길을 잃을 수 있다** — 의도된 긴장. 30분 타이머와 결합해 압박이 된다

안티필러 *"미니맵을 만들지 않는다"* 를 따른다.

### ① 렌더링 설정 — 확정

| 기능 | 설정 | 근거 |
|---|---|---|
| **Lumen (동적 GI)** | **끈다** (`r.DynamicGlobalIlluminationMethod=0`) | Section 2가 요구하는 것은 *"빛이 곧 가치"* 라는 **의도적으로 조작된 대비**다. Lumen의 자동 바운스가 이를 뭉갠다. 정적 모듈 기반 구조라 베이크 라이트맵이 훨씬 싸다 |
| **Nanite** | **유지** | 구매·AI 에셋은 **폴리곤 수가 예측 불가**하다. 예산 초과 에셋이 들어와도 프레임이 무너지지 않게 하는 **보험** |
| **Substrate** | 유지 | 셀 셰이딩을 Unlit 도메인으로 구현하면 무관. DefaultLit + 커스텀 라이팅이면 셰이더 비용 확인 필요 |
| Virtual Shadow Map | 재검토 | Lumen을 끄면 표준 Cascaded Shadow Map으로 대체 검토. 탑다운은 그림자 뷰 거리가 짧아 캐스케이드 수를 줄일 수 있다 |

> 🔴 **이 결정은 아직 프로젝트에 적용되지 않았다** (2026-08-11 확인).
>
> ```
> S1/Config/DefaultEngine.ini:12   r.DynamicGlobalIlluminationMethod=1    ← Lumen 켜져 있음
> S1/Config/DefaultEngine.ini:10   r.Shadow.Virtual.Enable=1              ← VSM 켜져 있음
> ```
>
> `docs/engine-reference/unreal/VERSION.md`는 같은 날 "Lumen ✅ 이 프로젝트 활성화됨"이라고
> 기록하고 있어 **문서 두 개가 서로 모순된다.** 적용 시점은 **넷코드·전투 작업 이후**로 미룬다 —
> 지금 끄면 기존 레벨의 라이팅이 전부 어두워져 작업 중인 것과 섞인다.
> 적용할 때 `VERSION.md`도 같이 고칠 것.

> ⚠️ **Nanite 유지가 데시메이트 공정을 없애주지는 않는다.**
> 로우폴리는 성능 문제이기 이전에 **비주얼 스타일**이다. 고폴리 메시에 플랫 셰이딩을 걸어도 로우폴리처럼 보이지 않는다.

#### 라이트맵 UV — 자동 생성으로 해결

Lumen을 끄면 정적 지오메트리에 **베이크 라이트맵**이 필요하고, 이는 **UV 채널 2개**를 요구한다.
구매·AI 에셋에는 대체로 없다.

**해결**: FBX 임포트 시 **`bGenerateLightmapUVs` 체크** (`FbxStaticMeshImportData.h:45`, 엔진 소스 확인됨).
UE가 자동 생성한다. 품질이 완벽하진 않지만 **로우폴리 모듈에는 충분**하다.

#### 30명 최악 케이스 검증 (2026-08-11 — 인원 100 → 30 반영)

가정: 몬스터 25 + 보스 1 + 드랍백 12 + 상자 15 (⑩ 참조 — **임의 가정값**)

```
플레이어   30 × 2,500 =  75,000
몬스터     25 × 1,200 =  30,000
보스        1 × 6,000 =   6,000
드랍백     12 ×   150 =   1,800
상자       15 ×   300 =   4,500
환경 (추정)             ≈ 95,000
──────────────────────────────────
총합                    ≈ 212,000 tri / frame      (이전 100명 기준 390,000)
```

> 60fps에서 초당 1,270만 tri. **삼각형 수는 이 프로젝트의 병목이 아니다.**
> 따라서 위 상한은 **성능 제약이 아니라 제작 시간·일관성 통제**를 위한 것이다.
> 진짜 병목은 드로우콜(⑤)과 CPU 애니메이션 갱신(⑦)이다.

### ③ 텍스처 전략 — 계층 분리

> 🔴 **팔레트 텍스처 방식은 기각.** UV 배치를 통제할 수 있어야 성립하는데, 구매·AI 에셋은
> UV가 이미 정해져 나온다. 팔레트를 쓰려면 받아온 에셋을 전부 리UV해야 해서 **오히려 가장 비싸다.**

| 대상 | 방식 | 이유 |
|---|---|---|
| **환경 모듈 · 소품 · 상자** | **버텍스 컬러** | 색이 2~4개면 충분. UV 불필요 |
| **무기 · 장비** | **버텍스 컬러** | 실루엣이 정체성. 색은 계열 구분만 |
| **캐릭터 베이스** | 원본 텍스처, **256px 제한** | 살결 · 눈 등 최소 디테일 |
| **전설 등급 히어로 아이템** | 개별 텍스처 허용 | 몇 개 안 되니 공들일 가치 |
| **UI 아이콘** | 아트라스 2048px 시트, 슬롯당 64~128px | |
| 환경 타일링 (예외 허용분) | 256px 기본, 최대 512px | Section 6 ③ |

#### 버텍스 컬러가 이 파이프라인에 맞는 이유

```
UV 언랩 불필요        ← 구매·AI 에셋의 UV를 안 건드려도 됨
텍스처 0장            ← VRAM 거의 안 씀
전부 같은 머티리얼     ← 자동 인스턴싱, 드로우콜 절감
Blender에서 면 선택 후 칠하기만
```

색 경계가 폴리곤 경계에 묶이는데, **각진 형태가 지배 형태**(Section 3 ③)인 설계에는 오히려 맞는다.

### ④ 머티리얼 — 통일이 핵심

| 카테고리 | 슬롯 상한 |
|---|---|
| 플레이어 베이스 바디 | 2 (바디 + 액센트) |
| 장비 각 파츠 | **1** — 전원이 **동일한 공유 머티리얼 애셋** 참조 |
| 몬스터 일반 / 보스 | 2 / 3 |
| 환경 구조 모듈 | 2 |
| 소품 · 드랍 아이템 | 1 |

> 🔴 **런타임에 `UMaterialInstanceDynamic`으로 색을 바꾸지 말 것.**
> MID를 만드는 순간 그 인스턴스는 "고유 머티리얼"이 되어 **자동 인스턴싱이 깨진다.**
> 인스턴스별 색상 변주가 필요하면 **Custom Primitive Data**(`SetCustomPrimitiveDataFloat()`)를 쓴다.
> **⑤의 드로우콜 계산이 성립하는 핵심 전제다.**

**셀셰이딩 마스터 머티리얼 1개**를 만들고, 모든 임포트 에셋에 이를 강제 적용한다.
원본 텍스처·노멀맵은 무시하거나 BaseColor로만 쓴다. 출처가 달라도 룩이 통일된다.

### ⑤ 드로우콜 예산 — **화면 내 동시 렌더 최악치**

> 🔴 **"최악 케이스"라는 라벨을 두 문서가 정반대 의미로 쓰고 있었다** (2026-08-11 발견).
>
> | 라벨 | 의미 | 쓰는 곳 |
> |---|---|---|
> | **Room 정원 최악치** | 한 Room에 30명 접속 | `game-concept.md` — **대역폭 산정** |
> | **화면 내 동시 렌더 최악치** | 30명이 한 화면에 보임 | 이 문서 — **렌더링 예산** |
>
> **아래 계산은 후자다.** 그런데 게임 디자인은 개활지 동시 가시를 **평균 1.9명**으로 설계했고,
> 30명 전원이 한 화면에 모이는 것은 **일어나지 않는 상황**이다.
>
> 따라서 **"예산의 14%밖에 안 쓴다"를 그대로 안전마진으로 읽지 말 것.**
> 여유는 진짜지만 **근거가 다르다** — 실제 운용 부하는 이보다도 훨씬 낮다.

> ✅ **2026-08-11 인원 축소(100 → 30)로 렌더링 예산이 크게 내려갔다.**
> 플레이어 드로우콜이 200 → 60으로 줄어 총합이 약 550~650 → **390~430**이 되었다.

```
플레이어 바디     30 × 2패스              =  60
장비 (자동 인스턴싱) 아이템 종류 50종 × 2   = 100   ← 인원이 아니라 종류 수에 비례
몬스터 25 + 보스 1                        =  52
드랍백 · 상자 (인스턴싱)                   =  15
환경 구조 (HISM, 모듈 타입당 1콜) 약 25종   =  25~40
소품 (HISM) 약 40종                       =  40~60
UI · 레이더 · 포스트프로세스                = ~100   (미니맵 폐지로 감소 여지)
──────────────────────────────────────────────
추정 합계                                 ≈ 390~430   (예산 3000의 약 14%)
```

**표준 기법만으로 여유롭다.** 단 세 조건이 지켜져야 한다.

1. 장비에 MID를 쓰지 않고 **Custom Primitive Data** 사용
2. 환경·소품은 개별 액터가 아니라 **HISM**(Hierarchical Instanced Static Mesh)으로 배치
3. 그림자 캐스팅 동적 라이트 수를 낮게 유지 (① Lumen 끄기와 연결)

> **결론: UE 5.8 신기능이 MVP에 필요하지 않다.** ⑨ 참조.

### ⑥ LOD 정책

#### 캐릭터 — LOD1 불필요

> ✅ **2026-08-11 개정으로 이 판단이 더 강해졌다.**
> Section 5는 "LOD1 = 미니맵용"이라 했으나, **미니맵 자체가 폐지되었다**(⑦ 레이더로 대체).
> 축소 렌더 대상이 아예 없으므로 캐릭터 LOD1을 만들 이유가 없다.

**확정: 레이더는 2D 아이콘 오버레이 방식.**

```
지형     없음 — 레이더는 지형을 표시하지 않는다
표시물   파티원 · 탈출 타워 · 루팅 가능 상자 → 2D 아이콘 스프라이트
```

`SceneCapture2D` 실시간 촬영이 불필요해져 **렌더 패스가 하나 줄어든다.**
지형 이미지를 미리 렌더할 필요도 없어져 **미니맵 대비 제작 공정이 통째로 사라진다.**
캐릭터는 **LOD0 단일 단계**만 제작한다.

#### 환경

- 탑다운 고정이지만 개활지가 넓어(Section 3 ①) 화면 하단 원거리 구조물은 화면 비율이 작아진다
- **화면 비율(ScreenSize) 기준** 전환: LOD0 유지 임계 ≈ 15~20%, 그 아래 LOD1(삼각형 40~60% 감소)
- 벽·바닥 등 반복 모듈은 HISM 배치이므로 LOD보다 **컬링 거리**가 주 통제 지점
- ✅ **카메라 확정 (2026-08-11)**: `TargetArmLength` **2,600** · FOV **60°** · pitch **−60°**
  → 화면 가로 30 m. LOD 전환 거리를 이 값에서 역산 가능. 상세는 `design/gdd/movement-camera.md` § Core Rule 8

### ⑨ 에셋 선별 기준 — 사기 전에 거른다

**환불이 안 되므로 구매 전 검증이 전부다.**

| 항목 | 통과 | 탈락 신호 |
|---|---|---|
| **셰이딩 전제** | 스타일라이즈드 / 플랫 / 셀셰이딩 카테고리 | PBR 리얼리즘 전용 (AO·Metallic·Roughness 풀세트) — 대부분 버려짐 |
| **노멀맵 의존도** | 노멀맵을 꺼도 형태가 유지됨 | 하이폴리 스컬핏을 베이크해 디테일 대부분이 노멀맵에 있음 → 밋밋해짐 |
| **폴리곤 성향** | 이미 로우폴리 | 수십만 tri 스컬핏 — 데시메이트해도 형태가 무너짐 |
| **머티리얼 슬롯** | 단일 또는 최소 | 슬롯이 많아 드로우콜 부담 |
| **형태 언어** | 각진 형태(Section 3 ③)로 최소 수정 가능 | 완전히 유기적·둥근 형태 — 수정 비용 > 구매 비용 |
| **라이선스** | "수정 후 커머셜 사용" 명시 허용 | 수정 금지 — 데시메이트·색칠이 필수이므로 자동 제외 |
| **최종 검증** | **32×32 축소 테스트**(Section 3 ①) 통과 | 구매 전 스크린샷을 축소해 형태가 안 읽히면, 예뻐도 이 게임엔 안 맞는다 |

> **가장 자주 예산을 낭비시키는 함정 3가지**: 셰이딩 전제 · 노멀맵 의존도 · 폴리곤 성향.
> 구매 전 반드시 이 셋부터 확인할 것.

#### 🔴 캐릭터 베이스 메시는 예외 — AI 생성 불가

```
단일 베이스 메시 + 장비 소켓 교체 (Section 5 ①②)
   → 리깅 · 스키닝 · 소켓 위치가 정확해야 함
   → 모든 장비가 같은 스켈레톤에 붙어야 함
```

**AI 자동 리깅은 이 요구를 못 맞춘다.** 본 이름·계층이 제각각이라 애니메이션 재사용이 불가능하다.

**해결**: 에셋스토어에서 **리깅된 스타일라이즈드 캐릭터 팩 하나**를 사서 베이스 메시로 고정.
장비는 그 스켈레톤의 소켓에 붙는 정적 메시로 AI/구매. 애니메이션은 팩 동봉분 또는 Mixamo 리타겟.

#### 필수 후처리 공정 — 에셋 하나당 반복

```
1. Blender 임포트
2. 데시메이트 (폴리곤 감축)        ← 스타일 통일의 핵심
3. 스무딩 정리 (Shade Flat / 하드 엣지)
4. 버텍스 컬러 칠하기
5. FBX 익스포트
6. UE 임포트 → 셀셰이딩 마스터 머티리얼 적용
   · Generate Lightmap UVs 체크
   · 텍스처 max size 제한
```

> ⚠️ **이것이 자산 하나당 고정 비용이다.** 에셋을 사거나 생성하는 것보다 이 공정이 더 오래 걸린다.
> 스코프 산정 시 반드시 계산에 넣을 것.

#### 익스포트 규격 (직접 모델링 시)
